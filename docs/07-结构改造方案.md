# 07 结构改造方案（v0.3 架构调整）

> **状态：已实现并落地**（`pnpm verify` 14/14）。实测：`/button/button` 页 4 个场景 + 右侧 Props 分组索引，点索引写 `#disabled` 并滚动到位；故意抛错的场景只显示错误卡片，其余场景照常渲染；Monaco 抽屉与 `editor.css` 按需加载正常。
>
> 与原方案的偏差：① 分组落地页（`groupIndex`）按拍板删掉；② API 摘要的信息来源是 `sceneMeta.api`（组件名 + prop 类型需要 manifest 才知道，暂未接到页面上）；③ 「在编辑器打开」同时在场景标题右侧与源码抽屉里可用，路径失效时降级为复制绝对路径；④ 参数区改为**就地渲染**（场景内、预览上方），右侧常驻面板列已删除——正文可用宽度从 612px 回到 1117px，出参走场景底部的折叠块。

> 起因：v0.1.5 的「一场景一屏」在真实接入（df-erp，406 组件 / 909 场景）下不可用——同一组件的十几个 prop 演示变成侧栏十几项，读者失去上下文。
> 参照对象：df-erp-static/playground（110 个组件页、909 条场景、页内右侧索引、每场景就近放 API 说明 / Payload / 调试 / 源码）。

## 0. 拍板结论

| 议题 | 决定 |
|---|---|
| 「页」怎么定义 | **目录约定**：一级目录 = 分组，二级目录 = 组件页，文件 = 场景 |
| 侧栏形态 | **改**：分组 → 组件页列表，页内场景用右侧索引（第三级） |
| 参数面板 | **表单为主，JSON 为辅** |
| 本地 IDE 打开 | **要做**（URL scheme，dev 与静态产物都可用） |

## 1. 目录约定

```text
scenes/
├── button/                      # 分组：Button
│   └── button/                  # 组件页：Button
│       ├── basic.vue            #   场景
│       └── size.vue
├── form/                        # 分组：Form
│   ├── input/                   # 组件页：Input
│   │   ├── basic.vue            #   场景
│   │   ├── disabled.vue
│   │   └── demos/
│   │       ├── DisabledTrue.vue   # 一场景多 Demo：每个 Demo 一个可独立拷贝的 SFC
│   │       └── DisabledFalse.vue
│   └── select/                  # 组件页：Select
│       └── basic.vue
└── internal/                    # 分组：Internal
    └── debug/                   # 组件页：Debug
        └── overview.vue         # 仍然支持 hideInNav + URL 直达
```

规则：

1. **一级目录 = 分组**，侧栏一级标题。
2. **二级目录 = 组件页**，侧栏二级条目。**必须三层**：分组目录下只能放页目录，不能直接放 `.vue`；`scenes/button/basic.vue` 这种扁平写法不再支持（项目尚未真正使用，不需要兼容层）。
3. **文件 = 场景**，页内一节；排序按 `sceneMeta.order`，未写的排最后。
4. 场景源码（含 `demos/`、`examples/` 下的文件）都可以通过 `sceneMeta.files` 进源码 Tab。

## 2. 页面结构

```text
[侧栏 260px]                [────────── 页正文 ──────────][─ 右侧索引 200px ─]
分组 A                      页标题 + 一行说明 · N 个场景      概要
  ├ 组件页 1  (3)                                              ├ 基础用法
  └ 组件页 2  (5)           ┌ 场景 1  「基础用法」 #anchor      Props
分组 B                        API 摘要：size: sm|md|lg = md     ├ 尺寸 size
  └ …                        预览：Note + Demo 栅格(1~2 列)      ├ 禁用 disabled
                             Payload / 调试（可选）             Events
                             源码：Tab（每 Demo 一份）           └ …
                            ├ 场景 2 …
```

- 正文单栏，最大宽度 880px；右侧索引 `position: sticky`，滚动高亮，点击滚动并写入 URL `#<场景id>`。
- 顶部工具栏**下沉到页头右侧**：宽度切换 / 主题 / 代码面板，减少常驻高度。
- 右侧索引分组固定顺序：**概要 → Props → Events → Exposes → Slots**，空组不显示（与 df-erp §3.2 一致）。

## 3. `sceneMeta` 扩展

```ts
export const sceneMeta = defineSceneMeta({
  title: '禁用 disabled',
  section: 'props',          // 新增：概要 | props | events | exposes | slots（索引分组）
  api: ['disabled'],         // 新增：本场景覆盖的公开 API，用于覆盖率判定
  order: 3,
  description: 'disabled 为 true 时不可点击，鼠标指针变为禁止。',
  files: ['src/scenes/form/input/demos/DisabledTrue.vue'],
})
```

- `section` + `api` 是这次新增的两个字段，其余保持。
- `api` 让 manifest 的覆盖判定从「prop 名出现在场景源码里」的启发式，升级为**显式声明**；未声明时回退到原启发式。
- 多 Demo 不改 `sceneMeta` 结构：布局交给框架提供的 `<PwDemoGrid>` / `<PwDemo>`，源码仍走 `files`。

## 4. 场景布局原语（新增）

| 组件 | 作用 |
|---|---|
| `<PwDemoGrid :columns="2">` | Demo 栅格容器，默认 1 列，可 2 / 3，窄屏自动折行 |
| `<PwDemo title="disabled = true">` | 单个 Demo 块：标题 + 控件区 + 可选 `#footer`（该 Demo 的 Payload） |
| `<PwSceneNote>` | 场景内说明引用块（替代现在的散装 `<p>`） |
| `<PwApiBrief :items="[{ api: 'size', type, default }]" />` | 场景顶部 API 摘要行，数据可直接来自 manifest |

## 5. 参数面板：表单为主，JSON 为辅

右侧面板 `PlaygroundInspectorPanel`：

```text
┌ 参数 ──────────────── [恢复默认] ┐
│ 文案  [点我 +1        ]          │   ← 表单（现有 useSceneArgs，改即生效）
│ 尺寸  [md ▾]                     │
│ 禁用  [ ○ ]                      │
├ JSON ────────────────────────────┤
│ [↳ props] [↰ modelValue] [↰ change]   ← Tab，input/output 图标区分
│ { "size": "md", … }              │
└──────────────────────────────────┘
```

- 表单始终在顶部，JSON 用 Tab，不抢主位。
- `useSceneOutput(() => ({ modelValue, change }))` 升级为多键：每个键一个 Tab，`{ label, kind }` 可选声明；未声明的键默认 `output`。
- `props` Tab 由框架自动生成（当前 args 快照），不需要场景写代码。

## 6. 本地 IDE 打开

**实现方式：URL scheme，不需要 dev server，静态产物同样可用。**

| 预设 | 打开方式 |
|---|---|
| `vscode` | `vscode://file/{绝对路径}:{行}` |
| `cursor` | `cursor://file/{绝对路径}:{行}` |
| `webstorm` | `webstorm://open?file={绝对路径}&line={行}` |
| `custom` | 自定义模板，`{file}` / `{line}` 占位 |

```ts
// playground.config.ts
export default defineConfig({
  editor: { preset: 'vscode' },            // 或 cursor / webstorm / custom
})
```

- 构建期把项目根绝对路径注入 `virtual:playground/config`；行号由插件在扫描时记录（`sceneMeta` 字段行 / prop 定义行）。
- 按钮位置：源码面板头部（当前文件 + 当前滚动行）、场景 API 摘要行右侧（打开 prop 定义）。
- 路径失效（项目不在原路径）时降级为「复制绝对路径」。
- **代价**：产物里会带本机绝对路径。要对外发布时设 `editor: { exposeRoot: false }`，按钮只在 dev 显示。

## 7. Demo 是否沙箱

**结论：不做 iframe / Shadow DOM 沙箱；做错误隔离 + 样式约束 + 预览懒挂载。**

判断依据：

- iframe 沙箱唯一真正必要的场景是「在浏览器里执行用户写的代码」（在线编辑器实时预览）。这个能力在 v0.1 已经砍掉（只在 dev 可用、生产做不到），现在没有复活计划。其余情况下 iframe 的代价过高：每个 Demo 一份 Vue 运行时、一页 N 个 Demo 就是 N 份内存，Teleport / 弹层全部失效，主题变量要手动穿透。
- Shadow DOM 看似更轻，但会打死所有走 `Teleport` 的弹层（下拉、Dialog、Tooltip），而组件库几乎都这么实现。收益（CSS 隔离）抵不上风险。
- 真正的痛点在别处：**一个场景抛错不应该白屏整页**；**一个场景的全局样式不应该污染别的场景和外壳**。这两件事用边界加构建期检查就能解决，不需要沙箱。

三层处理：

| 层 | 做法 | 成本 |
|---|---|---|
| 错误隔离 | 每个场景包一层 `onErrorCaptured`，渲染错误卡片（消息 + 场景文件路径 + 可展开栈）；Demo 级同样包一层。页内其它场景不受影响 | 低 |
| 样式约束 | 构建期检查场景文件：`<style>` 必须带 `scoped`，禁止 `:root` / `html` / `body` 选择器；命中则 dev 控制台告警并计入 `pnpm verify` | 低 |
| 预览懒挂载 | 视口外的场景只渲染标题 + 说明骨架，IntersectionObserver 进入视口才挂载 Demo。一页 13 个场景也只有 2~3 个活实例 | 中 |

**明确不做**：iframe、Shadow DOM、在浏览器里执行用户代码（含源码面板编辑实时预览）、跨场景共享状态。

**保留**：每个场景 / Demo 的组件实例相互独立；切页整页卸载，状态不残留。

已知限制（写进文档，不假装解决）：第三方库自带的全局样式（如 Element Plus 的 reset）仍会泄漏，只能靠场景自己加容器 class 兜。

## 8. 改造顺序（每步可独立验收）

| 步 | 内容 | 验收 |
|---|---|---|
| 1 | 插件：三级扫描（组 / 页 / 场景）+ `section` / `api` / 行号；manifest 覆盖判定改用 `api`，启发式兜底 | `virtual:playground/scenes` 每条带 `group/page/section/api`；示例 manifest 覆盖率不变 |
| 2 | 运行时：`PlaygroundPage` + `PlaygroundPageIndex` + 两级侧栏 + 路由 `/<group>/<page>#<scene>`；场景错误边界；预览懒挂载 | 滚动时索引高亮跟随；刷新 `#anchor` 定位正确；故意让一个场景抛错 → 只有该场景变错误卡片 |
| 3 | 场景原语 `PwDemoGrid` / `PwDemo` / `PwSceneNote` / `PwApiBrief` + 样式约束检查 | 一页 3~5 场景；一场景 2 Demo 并排 + 2 个源码 Tab；非 scoped 样式被 verify 报出 |
| 4 | 面板：`PlaygroundInspectorPanel`（表单 + JSON 多 Tab）+ 本地 IDE 打开 | 改表单实时生效；JSON Tab 有 props / modelValue / change；点按钮打开本机编辑器对应行 |
| 5 | 迁移三个示例（docs-site 9 / minimal-lib 6 / real-lib 7）到三级结构 | 三个示例 `pnpm typecheck` + `build` 通过，侧栏两级 |

## 9. 不破坏与删除项

保留：文件即场景、manifest / llms.txt / coverage、MCP 四个工具、深浅色、宽度切换、参数表单实时驱动、编辑器面板。

不引入：`vue-router`（继续手写 history）、任何 UI 库、iframe 沙箱。

删除：扁平目录兼容、M6 的分组落地页（`groupIndex` 与 `__index` 渲染分支）——侧栏两级已能表达，留着只是多一条死路。

## 10. 风险

| 风险 | 处理 |
|---|---|
| 一页 N 个场景 → N 个 Monaco 实例卡顿 | 页内源码默认用 shiki 静态块，点「在编辑器打开」才挂 Monaco（每页最多 1 个实例） |
| 右侧索引与滚动联动抖动 | 用 IntersectionObserver + 最近边界判定，不做逐像素 scroll 计算 |
| 绝对路径进产物 | `editor.exposeRoot: false` 可关；README 写明 |
| 迁移成本（已有 22 个场景） | 不做兼容层，三个示例一次性改到三级结构，作为新目录的样板 |
| 一页 N 个实例的状态残留 | 切页整页卸载；页内靠懒挂载控制活跃实例数 |
