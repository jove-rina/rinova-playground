## 三、踩坑记录

1. **shiki 双主题没颜色**：`defaultColor: false` 只输出 `--shiki-light*` / `--shiki-dark*` 变量，不写取色规则等于没高亮。
2. **`scrollbar-width` 会覆盖 `::-webkit-scrollbar`**：两个都写时 Chromium 用标准属性，滚动条变回常驻粗条。
3. **`startViewTransition` 里不等 `nextTick`**：快照还是旧主题，动画白做。
4. **`align-items: center` / 收缩画布会压扁百分比宽度组件**：`width: 100%` 在 shrink-to-fit 容器里按 min-content 解析（600px 表格被压到 247px），所以演示画布保持通栏 + 边框。
5. **布局改动误读**：用户说“太丑”指的是右侧索引面板，我先去改演示画布，返工一轮才对齐；改版式前应先确认指的是哪块。
6. **`@media` 里写 `.pw-head-btn--index { display: none }` 压不过后面的 `.pw-head-btn`**：需要带上父选择器提高特异性。
7. **`.gitignore` 里的裸 `logs` 会连 `docs/logs/` 一起忽略**：写完的日总结在 `git status` 里根本不出现，提交时才发现漏了；改成 `/logs`（只忽略根目录）。
8. **verify 的术语检查会扫 `docs/logs/`**：日志里复述旧术语会被判 FAIL，日志措辞改成「表示参数方向的两个旧中文词」，不去放宽检查本身。
