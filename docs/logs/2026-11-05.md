## 三、踩坑记录

1. **shiki 双主题没颜色**：`defaultColor: false` 只输出 `--shiki-light*` / `--shiki-dark*` 变量，不写取色规则等于没高亮。
2. **`scrollbar-width` 会覆盖 `::-webkit-scrollbar`**：两个都写时 Chromium 用标准属性，滚动条变回常驻粗条。
3. **`startViewTransition` 里不等 `nextTick`**：快照还是旧主题，动画白做。
4. **`align-items: center` / 收缩画布会压扁百分比宽度组件**：`width: 100%` 在 shrink-to-fit 容器里按 min-content 解析（600px 表格被压到 247px），所以演示画布保持通栏 + 边框。

6. **`@media` 里写 `.pw-head-btn--index { display: none }` 压不过后面的 `.pw-head-btn`**：需要带上父选择器提高特异性。
7. **`.gitignore` 里的裸 `logs` 会连 `docs/logs/` 一起忽略**：写完的日总结在 `git status` 里根本不出现，提交时才发现漏了；改成 `/logs`（只忽略根目录）。

发版踩坑（新增）：

1. **`~/.npmrc` 的 registry 是 npmmirror**：`npm whoami` 会报 `need auth`、`npm publish` 会发到镜像站。凡是发布/查线上版本都要显式 `--registry https://registry.npmjs.org`，`npm login` 也要带同一个 `--registry`，否则 token 写给了镜像。
2. **npm 12 的 `npm pack --dry-run --json` 返回对象不是数组**：key 是包名（`{"@rinova/playground": {...}}`），按数组解析会得到 `undefined`。预检脚本落成 `scripts/pack-check.mjs`（版本 / 文件数 / README / bin / main / types 是否真在包里）。
3. **旧 token 过期不会报得明显**：`npm whoami` 只给 `need auth`，要跑 `npm login --auth-type web` 重新授权（浏览器里点同意即可，不用在终端输密码）。
4. **端口被上一轮遗留进程占着会让 verify 假通过**：三个 dev server 若落在 5274 / 5281 / 5282，verify 探的是 `localhost:5273` 等固定端口，会打到旧进程或干脆跳过。先按命令行路径过滤杀掉本仓库的 `vite.js` 进程，再用 `grep Local:` 确认三个端口都对。
5. **版本脚本不要无脑改 `version`**：`packages/create-playground/template/package.json` 的 `version` 是生成项目的占位 `0.0.0`，只有依赖范围该跟着升。

新增踩坑：

1. **场景增删改原来不会重算清单**：`refresh()` 只 invalidate 了虚拟模块，`generateManifest` 只挂在组件变化上 —— MCP 与 llms 读到的页面表会一直停在 dev server 启动那一刻。修法：`refresh()` 里 `scheduleManifest(400)`，且定时器回调要先 `await ensureReady()` 再生成（否则用的是旧 `scenes`）。实测写入后 **607–755ms** 刷新。
2. **`scene_validate` 校验「还没进清单」的文件**：新场景写完到清单刷新之间有时间窗，只按 manifest 过滤会得到「0 个问题」的假通过。指定 `path` 时若清单里没有该条，按磁盘补一条再校验。
3. **指定 `path` 时不要跑页级规则**：否则会报一堆与这次改动无关的页绑定错误（fixture 里「好场景 0 问题」的断言就是这么挂的）。
4. **样式里的 `html {}` 原来是漏网**：`/(^|[},])\s*(:root|html|body)\b/g` 的 `^` 不是行首，必须加 `m` 标志，否则只匹配源码第一个字符位置。
5. **verify 里 `pageMeta`/`env` 这类「清单产物」检查要考虑 CI 没有 `.playground`**：文件不存在按「跳过」记录，存在但缺 `env` 段才算 FAIL —— 否则干净克隆上第一次跑 verify 必红。

下次接着做：0.6 仍是暂缓状态（要做先重跑 Monaco 体积 spike）；路线图上剩下的可选项是把 `scene_scaffold` 扩成「按覆盖报告批量补场景」，以及给 MCP 加 `--project` 之外的 workspace 多项目支持。

踩坑：

1. **`npx` 不锁版本会取 `latest`**：之前的「要写死版本」是对缓存延迟的防御，实际不是必须；真要防守就写 `@x.y.z`。文档默认改成不锁。
2. **客户端启动 MCP 的 cwd 不一定是项目根**：Cursor/Claude 常从包目录或临时目录启动，所以默认目录必须配合「向上找 6 层」，只认 cwd 会误报找不到清单。
