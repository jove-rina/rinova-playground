# 01 产品定义

## 1. 一句话定位

> rinova-playground：面向 Vue3 的「文件即场景」组件演示框架。你只放 `.vue` 文件，它负责侧栏、场景内源码、输入/输出面板、契约清单和 AI 可读的能力描述。

不宣称替代 Storybook；只管"组件能力怎么被看见、被试用、被 AI 读到"这三件事。

## 2. 要解决的问题

| # | 问题 | 现状 |
|---|---|---|
| P1 | 加一个演示太重 | Storybook 要写 `*.stories.ts` + 手写 argTypes + 维护 `main.ts`，安装 3~5 个包；Histoire 要写 `.story.vue` 且仍需注册 |
| P2 | 文档与代码会漂移 | 演示示例手抄组件代码，组件改了示例没改；或者示例没写全 props，读者永远看不到边界情况 |
| P3 | AI 读不到组件能力 | 组件库对 LLM 是黑盒：没有机器可读的 props/emit/slots 契约，也没有可执行的试用入口，AI 只能猜 |

一句话概括：**别人用不用，取决于"加一个场景要写多少代码"，而不是功能多少。**

## 3. 目标用户

| 用户 | 场景 | 他最在意 |
|---|---|---|
| A. 组件库 / 设计系统维护者 | 给内部或外部提供组件文档站 | 加场景快、文档不漂移、能对外发布 |
| B. 业务团队前端 | 把项目里的通用组件集中演示 | 零接入成本、不引入第二个构建体系 |
| C. AI 编码流程使用者 | 让 AI 改/写组件代码前先看真实能力 | 有机器可读契约、能跑起来验证 |

v0.1 的第一用户是 A，B 是接入方，C 是 M5 才兑现。

## 4. 使用场景

1. 组件库对外文档站（纯静态，可直接扔 CDN）
2. 内部组件库的"活文档"（改代码即改文档）
3. 给 AI 提供组件能力上下文（`manifest.json` + MCP 工具）

## 5. 差异化

| | Storybook | Histoire | rinova-playground |
|---|---|---|---|
| 加一个场景 | 新建 `*.stories.ts` + 手写 argTypes | 新建 `.story.vue` | **放一个 `.vue`，自动出现** |
| 输入/输出面板 | addon 手搭 | 自己接 | **内置**（`payload: { input, output }`） |
| 契约来源 | 手写 argTypes | 手写 | **`vue-component-meta` 自动提取** |
| 依赖重量 | 多包 + 独立构建器 | 中 | **1 个运行时包 + 1 个 Vite 插件** |
| 代码展示 | 只读高亮块 | 只读高亮块 | **可编辑的 Monaco（懒加载）+ shiki 只读回退** |
| AI | MCP（改 CSF 代码） | 无 | **manifest + MCP（改数据）** |

## 6. 成功指标（可测，不达标不发版）

| # | 指标 | 判定方式 |
|---|---|---|
| S1 | 0 → 首屏 ≤ 3 分钟 | 找一位没参与的人，从 `pnpm create` 计时到浏览器出现 5 个场景 |
| S2 | 命令数 ≤ 3、必需依赖 ≤ 1 | 数 `package.json` 里属于 playground 的 dependency |
| S3 | 加一个场景 = 新建 1 个文件 | 新建文件后不改任何其他文件，侧栏即出现 |
| S4 | 不要求使用者写 playground 自己的组件 | 统计场景文件中的 import：只允许 vue + 自己的组件库 + 可选的 `defineSceneMeta` |
| S5 | 首屏 JS 不含编辑器代码 | 运行时包无编辑器依赖，`dist/` 共 1.1MB，无 monaco 产物 |
| S6 | 构建产物纯静态 | `pnpm build` 后 `dist/` 可直接静态托管，无服务端依赖 |
| S7 | 零后端、零 telemetry、零账号 | 全局搜索无上报域名 |

## 7. 非目标（v0.1 明确不做）

鉴权与登录、菜单权限码、多语言、视觉回归基线、插件系统、主题可视化编辑器、浏览器内实时编译场景代码、SSR、云端托管服务、组件市场。

## 8. 产品承诺与边界

- **承诺**：场景是普通 Vue 组件，能 `pnpm dev` 就能进 playground；侧栏结构来自目录，不来自配置。
- **边界**：playground 不接管构建（用户自己的 Vite 配置仍有最高权），不改写用户组件，不要求组件符合任何约定（不依赖 Props 命名规范）。
