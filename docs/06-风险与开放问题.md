| R13 | 插件提供的是应用级单例：一个场景改了 pinia / 全局组件注册，其它场景静默受影响 | 排查成本高，会被当成框架 bug | 文档写明（02 §3.9.1）；测试床加一条反向断言（两个场景互不影响）；真隔离只能 iframe，已在 07 §7 否决 |
| R14 | `globals` 明文进 bundle，消费端把 token / 密钥写进去 | 泄露 | 配置项注释 + 02 / 03 双处警告；测试床示例只用 `apiBase` / `appName` 这类公开常量，需要 token 一律走插件运行时获取 |
| R15 | 插件 UI 用第三方库，在暗色外壳下不跟随主题（黑底黑字） | 用户以为框架有 bug | 框架只提供 `usePlaygroundTheme()` 与 `--rp-*` 变量，不替第三方库切 `dark` class；测试床示例演示正确接法 |

## 2. 开放问题（需要决策，未拍板不实现）

| # | 问题 | 备选 | 建议 |
|---|---|---|---|
| Q1 | 是否需要"组件页"（一个组件的所有场景聚合 + props 表） | 只靠目录分组 / 增加组件聚合页 | **v0.2 已落地**：`groups` 配组名 + `groupIndex` 给每个分组合成落地页（`<分组>/__index`），点分组标题进入；不做独立的"组件页"概念 |
| Q2 | 编辑模式改动去向 | 只在内存 / 回写磁盘（dev 期能力）/ 生成 patch | **推迟到 v0.3**：v0.1 决策为不做编辑，v0.3 若有真实需求再评估 |
| Q3 | 内置 shiki 主题集 | 只给 2 套（light/dark）/ 暴露全部 | 内置 2 套（`light-plus`、`tokyo-night`），随外壳明暗切换；不再暴露主题名配置（v0.4 删掉了未接线的 `theme.code`） |
| Q4 | 是否对外提供英文文档 | 仅中文 / 双语 | v0.1 仅中文；有外部使用者后再补英文 |
| Q5 | 大文件降级阈值 | 1000 / 2000 / 5000 行 | 暂定 2000 行，M2 用真实文件实测后调整 |
| Q6 | 是否支持 React / Svelte | 不支持 / 后续 | 明确不支持，框架只做 Vue3 |
