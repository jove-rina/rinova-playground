# 06 风险与开放问题

## 1. 风险清单

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| R1 | Monaco 体积让"轻量"标签站不住 | 首屏变慢、被拿 Storybook 对比 | 懒加载（首屏零编辑器代码）+ 体积预算（编辑器 chunk gzip ≤ 2.5MB）+ `codeViewer: 'shiki'` 开关 + 断网降级 |
| R2 | Vite 8（rolldown）下 Monaco worker 打包与 `?worker` 行为未验证 | M2 卡住，可能回流重构 | M2 第一步先做 spike（半天）：验 worker 产物数量、gzip、dev/build 双跑 |
| R3 | `@shikijs/monaco` 用 textmate 替换 Monaco 自带高亮 | Monaco 的语义高亮（未使用变量变暗、类型灰化）失效；两套坐标不一致的观感问题 | 明确不做语义高亮，只承诺"语法高亮与静态块一致"；TS 语义能力仍走 worker 的补全与诊断 |
| R4 | `vue-component-meta@3.3` 与 TypeScript 7 的兼容性未知 | M3 契约提取失败 | M3 开工前先跑一次最小提取；不行就锁 TS 5.x/6.x |
| R5 | 自研原语范围失控，长成第二套 UI 库 | 维护成本翻倍、与"D2 不做 UI 库"矛盾 | 硬约束 ≤ 900 行、只做清单内 8 个组件、不对外导出 |
| R6 | 场景与预览无 DOM 隔离，非 scoped 样式互相污染 | 用户以为框架有 bug | v0.1 文档明确要求 scoped；预览区默认挂载在与外壳不同的 DOM 子树，避免外壳样式被覆盖 |
| R7 | Storybook 惯性：被当成"另一个 Storybook 但功能少" | 无人采用 | 定位只讲"文件即场景 + 入参出参 + AI 可读"，不讲替代 |
| R8 | 没有 dogfood 就没有说服力 | 开源后无人用 | `examples/real-lib` 必须是真实组件库（M4 前定）；找 2 位外部使用者验收 |
| R9 | 文档成本被低估 | v0.1 发不出去，或发出去没人会接 | M4 用真人验收代替自评；文档站自己搭自己 |
| R10 | 200+ 场景时侧栏与扫描性能下降 | 大项目体验崩 | M1 就压测 200 场景；必要时侧栏虚拟滚动 |
| R11 | 无测试基线的惯性（旧习惯） | 后续改动靠肉眼 | 每个里程碑必须有 `scripts/verify-*` 脚本，验收项可脚本化的一律脚本化 |

## 2. 开放问题（需要决策，未拍板不实现）

| # | 问题 | 备选 | 建议 |
|---|---|---|---|
| Q1 | 是否需要"组件页"（一个组件的所有场景聚合 + props 表） | 只靠目录分组 / 增加组件聚合页 | v0.1 先只靠目录分组；M3 契约清单出来后再看是否需要聚合页 |
| Q2 | 编辑模式改动去向 | 只在内存 / 回写磁盘（dev 期能力）/ 生成 patch | v0.1 只在内存 + 复制下载；dev 回写留给 v0.2 评估 |
| Q3 | 内置 shiki 主题集 | 只给 2 套（light/dark）/ 暴露全部 | 内置 2 套（`vitesse-light`、`vitesse-dark`），其余由用户传主题名，按需动态加载 |
| Q4 | 是否对外提供英文文档 | 仅中文 / 双语 | v0.1 仅中文；有外部使用者后再补英文 |
| Q5 | 大文件降级阈值 | 1000 / 2000 / 5000 行 | 暂定 2000 行，M2 用真实文件实测后调整 |
| Q6 | 是否支持 React / Svelte | 不支持 / 后续 | 明确不支持，框架只做 Vue3 |

## 3. 已定决策记录（ADR 摘要）

| 日期 | 决策 | 结论 | 依据 |
|---|---|---|---|
| 2026-11-02 | DX 主线 | 文件即场景：零注册、零 API、零配置改动 | 采用门槛取决于"加一个场景写多少代码"，不是功能多少 |
| 2026-11-02 | UI 依赖 | 不使用 Element Plus，自研 8 个基础通用组件（≤ 900 行） | 框架要能被任意团队接入，不能绑定 UI 库 |
| 2026-11-02 | 代码高亮 | 统一 shiki 4.6，静态块与编辑器共用同一 highlighter 实例 | 避免"展示一套色、编辑一套色" |
| 2026-11-02 | 图标 | `@lucide/vue` 按需引入 | 轻、tree-shake、与 shiki/Monaco 无耦合 |
| 2026-11-02 | 代码展示形态 | 使用 Monaco 0.57（非只读 code block、非 CodeMirror） | 后续代码扩展能力（编辑、diff、AI 改写）需要真正的编辑器 |
| 2026-11-02 | Monaco 集成方式 | `@shikijs/monaco` 注入 shiki highlighter | 与已定的 shiki 基线一致，主题只需一处维护 |
| 2026-11-02 | Monaco worker | 仅 `editor` + `ts` | 展示场景不需要 json/css/html 语义，产物少一半 |
| 2026-11-02 | Monaco 版本 | 0.57.0（不对齐旧项目 0.52） | 新仓库无历史约束，直接取当前版本 |
| 2026-11-02 | 实现方式 | 在 rinova-playground 内重新实现，不迁移任何既有代码 | 避免把旧项目的 ERP 接缝和历史包袱带进框架 |
| 2026-11-02 | 包名 | 全部不带 npm scope：`rinova-playground` / `rinova-playground-vite` / `create-rinova-playground` / `rinova-playground-mcp` | 创建命令即 `pnpm create rinova-playground`，无需申请 scope；后续若需要再迁移 |
