# 03 功能规格与验收

每个功能都给出**行为 / 边界 / 可测验收**。验收不通过则不进里程碑。

## F0 结构（v0.3，已实现）

**行为**
- 目录必须三层：`scenes/<分组>/<组件页>/<场景>.vue`；分组目录下直接放 `.vue` 会被忽略并告警
- 侧栏两级：分组 → 组件页（页名后跟场景数）；页内纵向堆场景，右侧 sticky 索引
- 索引分组固定顺序：概要 → Props → Events → Exposes → Slots，空组不显示；`sceneMeta.section` 决定归属
- `sceneMeta.api` 显式声明本场景覆盖的 API，显示为标题下方的标签
- 页标题/说明/排序来自 `<页>/meta.ts` 的 `pageMeta`

**验收（实测）**
1. `/button/button` 侧栏显示「Button 4」「Card 1」，隐藏场景所在的页不出现在侧栏
2. 索引点击后 `#disabled` 写入 URL，高亮跟随，落点偏差 ≤ 8px
3. `sceneMeta.api: ['disabled']` 在标题下方渲染为 `disabled` 标签

## F1 场景发现与侧栏

**行为**
- 构建期与 dev 期扫描 `scenes` 目录，按目录层级生成侧栏树
- 新增、删除、重命名场景文件后，dev server 热更新侧栏，不重启
- 同层排序：`sceneMeta.order` 优先，其次文件名升序；目录始终排在场景之前

**边界**
- 空目录不渲染为空分组
- 同一目录下场景与子目录同名时，以完整路径作为 id 去重
- 文件解析失败（SFC 编译错误）时，侧栏保留该项并标记错误态，其余场景仍可访问

**验收**
1. 新建 `scenes/button/disabled.vue` 保存后 ≤ 1s 内侧栏出现该项
2. 删除该文件后侧栏项消失，浏览器地址若指向该场景则回落到第一个场景
3. 侧栏树与磁盘目录结构 100% 一致（脚本比对，不靠肉眼）
4. 写 `sceneMeta.title` 后侧栏与面包屑立即显示该标题（中文可用）；`order` 改变同层排序；`hideInNav` 的场景不出现在侧栏但 URL 直达可用
5. 配 `groups` 后分组标题显示中文自定义名，**声明顺序即侧栏顺序**（实测 `{index, tao-common, tao-icon, tao-action-button, tao-page-layout, tao-separator}` → 侧栏 `文档 / Tao 通用组件 / 图标 / 操作按钮 / 页面布局 / 分隔面板`）
6. 配 `groupIndex: true` 后每个分组自动多一个「概览」页（id `<分组>/__index`）：点分组标题进入，列出该组场景标题 + 描述 + 场景 id；合成页没有源文件，不计入侧栏底部「N 个场景」

## F2 预览区（v0.3 更新）

**行为**
- 一个页里纵向渲染该页所有场景；每个场景 = 标题（`#锚点` + 「在编辑器打开」）+ 说明 + API 标签 + 预览 + 折叠源码
- 预览懒挂载：视口外只渲染骨架，`IntersectionObserver` 进入 600px 内才挂载真实组件
- 场景错误边界：`onErrorCaptured` 捕获后渲染错误卡片（消息 + 场景文件 + 可展开调用栈），页内其它场景不受影响
- 场景内可用 `<PwDemoGrid>` / `<PwDemo>` 并排多个 Demo，每个 Demo 一套独立的 `useSceneArgs` 槽位

**验收（实测）**
1. 故意 `throw` 的场景显示错误卡片，其余 4 个场景照常渲染，无 Vite 错误遮罩
2. 一页 5 个场景时首屏只挂 2 个实例，滚动到第 5 个才加载
3. 窄屏（<900px）Demo 栅格自动折成单列

**宽度与视口**
- 页头三档：自适应 / 平板 820px / 手机 420px，作用于正文容器

**边界**
- 场景内的全局样式（非 scoped）不做沙箱隔离（明确不上 iframe / Shadow DOM，见 07）；构建期检查 `<style>` 必须带 `scoped`、禁止 `:root` / `html` / `body`

## F3 代码展示区（v0.1 核心，Monaco）

**行为**

| 能力 | 规格 |
|---|---|
| 实现 | `monaco-editor@0.57`，通过 `@shikijs/monaco` 使用 shiki 高亮；`codeViewer: 'shiki'` 时回退为只读高亮块 |
| 加载时机 | **懒加载**：首次打开代码 Tab 或切到编辑态时才 `import()`，首屏 JS 中不含编辑器代码 |
| 默认模式 | 只读。只读态保留：搜索（⌘/Ctrl+F）、折叠、选择、复制、行号、链接分享 |
| 多文件 | 场景源文件 + `sceneMeta.files` 逐个 Tab 展示；Tab 顺序 = 场景文件在前 |
| 搜索 | 使用 Monaco 内置查找面板，替代自研搜索条；面板样式必须套用 12 个 CSS 变量 |
| 折叠 | 支持代码折叠、折叠全部；折叠状态在同一会话内记忆 |
| 大文件 | > 2000 行时自动降级为"只读 + 静态 shiki 渲染"，不挂编辑器 |
| 主题 | 与静态代码块共用同一个 shiki highlighter 实例与主题名 |
| 错误态 | 场景无法加载时展示错误信息与文件路径，不用空白页 |

**边界**
- Monaco 失败（worker 加载失败、内网 CDN 拦截）时**自动降级**为静态高亮块，不阻塞页面
- 编辑器容器尺寸变化由 `ResizeObserver` 驱动 `layout()`，不监听 `window.resize`
- 同一文件在多个 Tab 打开时复用同一个 model，避免重复 tokenize

**验收**
1. 进入首屏后 Network 面板中 monaco 相关请求数 = 0；打开代码 Tab 后编辑器 chunk 请求 ≤ 3
2. 编辑器与静态代码块的同一段源码 token 颜色逐色一致（截图取色对比）
3. 只读态按 `⌘/Ctrl+F` 弹出查找面板并命中；按 `⌘/Ctrl+A` 全选复制得到完整源码
4. 关闭代码 Tab 后编辑器实例被 `dispose`（DevTools 中无残留 DOM 与计时器）
5. 把网络断掉再打开代码 Tab，自动降级为静态高亮，页面无报错弹窗
6. 2500 行示例文件打开时不挂编辑器，滚动无卡顿

## F4 入参 / 出参（v0.3：就地参数区）

**行为**
- 入参：场景用 `useSceneArgs(defaults, { options, labels })` 声明；面板渲染成**表单**（boolean→开关、number→数字框、string→文本框、有 options→下拉），改动直接写回场景的响应式对象，组件立即重渲染
- 出参：`useSceneOutput(() => ({...}))`，面板每 400ms 轮询，JSON 用 shiki 高亮
- 面板固定在预览区右侧，宽 320px，入参 / 出参两个 Tab；入参 Tab 右上角有「恢复默认值」
- 未声明任何一项的场景，「参数」按钮禁用，面板不出现

**边界**
- 入参表单是纯客户端响应式，**dev 与生产静态站行为一致**，不依赖任何服务端接口
- 出参 getter 抛错时在面板里显示错误文本，不中断场景
- 场景卸载反注册，切换场景不会残留上一个场景的值

**验收**
1. 改「尺寸」下拉 → 预览组件尺寸立即变化（实测 md 32px → lg 40px / sm 26px）
2. 切换「禁用」开关 → 组件变为 disabled
3. 改「文案」输入框 → 组件文本实时更新
4. 点「恢复默认值」→ 三个入参回到初始值
5. 生产构建（`pnpm build` + 静态托管）下以上行为一致
6. **一场景多 demo**：同一场景声明两块 `useSceneArgs(..., { slot })`，面板出现两块带槽位标题的表单（实测 `主按钮 / 次按钮`），改一块不影响另一块；`useSceneOutput(getter, slot)` 两个槽位各自出参（实测 `{clicked:1}` / `{clicked:2,doubled:4}`）；每块有独立「只恢复这一块」按钮，顶栏按钮恢复全部

**行为（v0.3 改版）**
- 参数表单**渲染在场景内部**、预览下方（与出参同一位置），两列栅格；不再有常驻的右侧面板列
- 每个场景只显示自己的槽位（`useSceneArgs` 的 `slot` 分块），一页多场景互不干扰
- 页头「参数」按钮控制所有参数区显隐，默认展开
- 出参收在场景底部「出参 · N 个槽位」折叠块里，多槽位用胶囊 Tab 切换，500ms 轮询
- 文案/尺寸/开关改了立即作用于该场景的组件（纯前端，静态站同样可用）

**验收（实测）**
1. 改尺寸 md → lg：按钮高度 32px → 40px
2. 一页 5 个场景时只有当前场景的参数区出现（多 demo 场景显示「主按钮 / 次按钮」两块）
3. 正文可用宽度从 612px（右侧面板方案）回到 1117px
4. 关闭「参数」按钮后参数区全部收起，预览不受影响

## F5 主题

**行为**
- 外壳主题只由 12 个 CSS 变量驱动（见 04 文档），支持 `light / dark / auto`
- 代码主题由 shiki 主题名驱动，编辑器与静态块一致
- `theme.ui` 与 `theme.code` 相互独立可配

**验收**
1. 覆盖任意外壳变量后，所有自研组件同步变色，无硬编码颜色漏出（全局搜索十六进制色值，仅允许出现在变量定义文件）
2. 切到 dark 时编辑器背景与预览区背景色差 ΔE ≤ 3（避免"黑块套黑块"）

## F6 检索与快捷键

| 快捷键 | 行为 |
|---|---|
| `⌘/Ctrl + K` | 打开场景搜索（按标题、路径、tags） |
| `⌘/Ctrl + F` | 聚焦到代码区查找（编辑器内） |
| `⌘/Ctrl + .` | 展开 / 收起侧栏 |
| `Esc` | 关闭浮层 / 退出全屏 |

**验收**：在 200 个场景规模下，搜索输入首字到结果渲染 ≤ 100ms

## F7 构建产物

**行为**
- `pnpm build` 输出纯静态站点，含 `manifest.json`（M3 起）
- 支持 `base` 子路径部署；history 路由要求服务端把未匹配路径 rewrite 到 `index.html`（dev / preview 内置，静态托管需自行配置）
- 产物中不包含 sourcemap 默认输出、不包含 telemetry

**验收**
1. `dist/` 通过任意静态服务器（`python -m http.server`）在 `/sub/path/` 下可正常访问
2. 产物 gzip 后：首屏 JS ≤ 300KB（不含编辑器 chunk）；编辑器 chunk ≤ 2.5MB（含 ts worker）
3. 外壳 CSS 与编辑器 CSS 分离：`@rinova/playground/style.css` = 20.1 KB（gzip **3.8 KB**），`@rinova/playground/editor.css` = 381.7 KB（gzip 124.9 KB）；后者由包内 `loadMonaco()` 动态 `import`，**只有打开代码面板时才请求**（实测首屏无该请求、点「代码」后出现）；`codeViewer: 'shiki'` 的项目永不加载它

## F8 契约清单 manifest（M3，已实现）

**行为**
- dev server 启动、构建、以及组件文件变更（防抖 800ms）时，用 `vue-component-meta` 从 `config.components` 匹配的组件里提取 props / emits / slots / exposed
- 过滤 Vue 透传 props（`key` / `ref` / `class` / `style` / `onVue:*`），只留组件自己声明的
- 产出三份文件到项目根的 `.playground/`：`manifest.json`、`llms.txt`、`coverage.md`；`pnpm build` 时再复制进 `dist/`
- 覆盖判定：某个 prop 名出现在关联场景的源码里即视为「有场景覆盖」；报告列出全部未覆盖 props

**边界**
- 未配置 `components` 时完全不生成，也不影响 dev/build
- 提取失败（tsconfig 缺失等）只打警告，不中断构建

**验收**
1. manifest 中 prop 的名称、类型、默认值与源码声明一致（实测 `size: "md" | "sm" | "lg" | undefined, default="md"`）
2. 故意留空的 prop 被报告出来（实测给 MyButton 加 `loading` 但不写场景 → 覆盖 5/6，`loading` 标为未覆盖）
3. 组件文件保存后 `.playground/` 800ms 内自动更新

## F9 AI 能力（M5，可选包）

**行为**
- `@rinova/playground-mcp`：stdio MCP server，读 `.playground/manifest.json`，只读
- 已实现 4 个工具：`capability_search`（关键词找组件）、`capability_get`（完整契约 + `文件:行号`）、`scenario_list`（场景列表，可按组件过滤）、`coverage_report`（未覆盖 props）
- 入参 `--project <dir>` / `--manifest <file>`；清单缺失时直接给出「先跑 pnpm dev 并配好 components」的提示
- 写场景仍然靠人/AI 直接写 `.vue` 文件，MCP 不引入注册 API

**未实现（留到后续）**
- `capability.try`：需要无头浏览器渲染 + emit 记录 + 截图，成本高，暂不做
- `capability.author`：生成场景属于「AI 写文件」，交给客户端自带的文件工具即可，不必包进 MCP

**验收（实测 7/7）**
1. `initialize` 握手返回 `{name: rinova-playground, version: 0.1.0}`
2. `tools/list` 暴露 4 个工具
3. `capability_get("MyButton")` 返回 5 个 prop，每个带 `MyButton.vue:行号`
4. `coverage_report` 返回 `覆盖 5/6` 并列出未覆盖的 `loading`
5. 未知组件返回 `isError: true`
