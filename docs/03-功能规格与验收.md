# 03 功能规格与验收

每个功能都给出**行为 / 边界 / 可测验收**。验收不通过则不进里程碑。

## F0 结构（v0.3，已实现）

**行为**
- 目录必须三层：`scenes/<分组>/<组件页>/<场景>.vue`；分组目录下直接放 `.vue` 会被忽略并告警
- 侧栏两级：分组 → 组件页（页名后跟场景数）；页内纵向堆场景，右侧 sticky 索引
- 索引分组固定顺序：概要 → Props → Events → Exposes → Slots，空组不显示；`sceneMeta.section` 决定归属
- `sceneMeta.api` 显式声明本场景覆盖的 API，显示为标题下方的标签
- 页标题/说明/排序来自 `<页>/meta.ts` 的 `pageMeta`

**验收（实测）**
1. `/button/button` 侧栏显示「Button 4」「Card 1」，隐藏场景所在的页不出现在侧栏
2. 索引点击后 `#disabled` 写入 URL，高亮跟随，落点偏差 ≤ 8px
3. `sceneMeta.api: ['disabled']` 在标题下方渲染为 `disabled` 标签

## F1 场景发现与侧栏

**行为**
- 构建期与 dev 期扫描 `scenes` 目录，按目录层级生成侧栏树
- 新增、删除、重命名场景文件后，dev server 热更新侧栏，不重启
- 同层排序：`sceneMeta.order` 优先，其次文件名升序；目录始终排在场景之前

**边界**
- 空目录不渲染为空分组
- 同一目录下场景与子目录同名时，以完整路径作为 id 去重
- 文件解析失败（SFC 编译错误）时，侧栏保留该项并标记错误态，其余场景仍可访问

**验收**
1. 新建 `scenes/button/button/disabled.vue` 保存后 ≤ 1s 内侧栏出现该项
2. 删除该文件后侧栏项消失，浏览器地址若指向该场景则回落到第一个场景
3. 侧栏树与磁盘目录结构 100% 一致（脚本比对，不靠肉眼）
4. 写 `sceneMeta.title` 后侧栏与面包屑立即显示该标题（中文可用）；`order` 改变同层排序；`hideInNav` 的场景不出现在侧栏但 URL 直达可用
5. 配 `groups` 后分组标题显示中文自定义名，**声明顺序即侧栏顺序**（minimal-lib 实测：`button → card → input → table → form`，与 config 一致；改前 Form 会因 `pageMeta.order=4` 插到 Table 前面）
6. **一组多页**：`scenes/card/card/` 与 `scenes/card/plain/` 两个页同属 Card 组，侧栏 `CARD → Card(4) / Plain(1)`，两条都能点开；路由 `/card/card` 与 `/card/plain` 各自独立；页项相对组标题缩进 8px（实测文字起点 16px vs 8px）
7. 组内页顺序按 `pageMeta.order`：`card` 下 `card(order 1)` 在 `plain(order 2)` 之前
8. 页头面包屑 = 分组标签（实心圆角标签）› 页名 ｜ 场景数：`/card/plain` 显示 `[Card] › Plain ｜ 3 个场景`，中间是 12px 的 `ChevronRight`（`text-muted 70%`、两侧 gap 8px 再收 2px），场景数用 1px 竖线隔开、11.5px 弱化，不再贴着一串词读；`/card/card` 与 `/button/button` 因为组名等于页名只显示页名（不出现 `Button Button` 这种重复）；整串带 `aria-label="当前页面位置"` 与 `title="分组 › 页名"`（实测 `/intro/overview` 分组文字、页名、场景数分别落在 x=324 / 380 / 424）
9. **左边缘对齐（1440 视口实测）**：页头标签文字、说明、场景标题、预览卡片、API 表都在 **284px**（标签盒子 275px，用 `margin-left: -9px` 抵消 8px 内边距 + 1px 边框）；侧栏 logo / 搜索框 / 分组标题同在 **16px** 导轨，页项盒子 16px、文字 **24px**（缩进一级）
10. API 表头不折行：`默认值` 这类两字/三字表头在列宽自适应时保持单行（表头 `white-space: nowrap`，实测表头高 33px）
11. **侧栏折叠**：页头左侧按钮或品牌条右侧按钮收起侧栏（宽度 260 → 0，正文左移 260），状态写 `rinova-playground:sidebar-open`，刷新后保持
12. **分组折叠**：分组标题为整行 28px 高的按钮，文字落在 16px 导轨上，箭头在右；默认只展开当前页所在分组（实测进入 `/button/button` 时只有 BUTTON 展开，其余 4 组收起到一行）；收起的分组标题右侧显示该组页数（`CARD` 展开时不显示，收起时显示 `2`）
13. **导航层级与可达性**：组件页行高 28px、文字 24px、页项之间 2px、分组之间 6px；子组件页缩进到 40px，用一根短竖线表示归属（`.pw-nav-children::before`：x=28、`top:-2px`、`bottom:1px`、2px 宽、两端 2px 圆角、`text-muted 16%`，**整条线保持中性**），只有当前页对应的那一段才用品牌色（`.pw-nav-item.is-child.is-active::before`：x=28、高 28px、实心品牌色），不做每项一个 `└` 的梯子，也不整条线变蓝；页项不再显示场景数（hover `title` 里给 `Table · 3 个场景`）；分组标题 `position: sticky` 吸顶；当前页被收起在某个分组里时，该标题用品牌色 + 品牌色徽标标出，不会“找不到自己”；查看子页时父页文字与箭头给 72% 品牌色（`is-branch-active`）表示“当前页在它下面”；当前页带 `aria-current="page"`；**点父页即进入并自动展开它的子页**（实测 `/card/plain` 点 `Card` → `/card/card` 且子项可见），深链到父页 `/card/card` 也自动展开，右侧箭头只负责收起/展开、不跳页；分组箭头与页项箭头的中心都落在 218px
14. **导航不设键盘快捷键**：侧栏没有全局快捷键，也没有 `↑`/`↓`/`Home`/`End` 的列表焦点移动（用户明确要求去掉，Tab 仍可正常逐项聚焦）。只保留搜索框自己的两个键：`Enter` 直接进入第一条命中（实测输入 `table` 回车落到 `/table/table`）、`Esc` 先清空再退出；搜索态下分组标题不可折叠（`disabled`）
15. **搜索是全局的**：输入后列出「页面」与「场景」两段命中（页面按页名 / 页 id / 分组名，场景按场景标题 / 文件名 / 路径 / 说明 / 标签 / 覆盖的 API 名），场景命中带 `分组 · 页面` 副行、命中 API 名时追加「覆盖 xxx」胶囊；点页面切页，点场景切页并滚到那一个场景；命中片段用 `<mark>` 标出（品牌色 24% 底、加粗）；无结果时给「没有匹配… `Esc` 清空」
16. **Markdown 场景**：页面目录下放 `.md` 即为场景，不需要 `<script>`；frontmatter 支持 `title` / `order` / `tags` / `description` / `section` / `api` / `showSource`；正文的 `::: tip|info|warn|danger 标题` 渲成 `PwCallout`、`::: steps` + 有序列表渲成 `PwSteps`；代码块按语言用 shiki 高亮（实测 4 个代码块全部 `pre.shiki`，3 条步骤带序号圆圈）
17. **内容页不展示源码**：优先级「场景 `showSource` > 页 `pageMeta.showSource` > 全局 `sources`」，`.md` 场景默认 `false`；不绑组件的页必须显式 `showSource: false`（verify 运行时会逐页检查，minimal-lib 3 个内容页、docs-site 3 个内容页均为 false，页面里 `.pw-source` 数量为 0）
18. **公共排版组件**：`PwProse` / `PwCallout`（四种 tone + 图标）/ `PwSteps` + `PwStep` / `PwMarkdown` / `defineMarkdownScene` 全部从 `@rinova/playground` 导出；`.pw-prose` 是不带 scoped 的公共样式，Markdown 与手写 Vue 内容页共用同一套（prose.less 228 行、只取主题变量、无硬编码色值）
19. **文档场景布局**：`pageMeta.doc: true` 或 `.md` 场景时该页按文档排版渲染 —— 不套演示画布（`.pw-scene__canvas` 数量 0）、场景标题 18px 充当 h1、正文 720px；组件页保持画布 + 源码卡片
20. **代码块复制与高亮**：Markdown 与手写内容页共用一条增强路径（`components/prose/enhance.ts`）—— 渲染后就地替换成 shiki 结果、左上角出语言角标、悬停/聚焦右上角出「复制」按钮（`padding-top: 27px` 保证按钮不压第一行）；点击复制的是 `<code>` 的纯文本，按钮变「已复制」并在 1.2s 后复原（实测 `navigator.clipboard` 写入内容与代码块逐字相等）；语法高亮用 shiki 双主题，**必须由 `.pw-prose` 自己把 `--shiki-light*` / `--shiki-dark*` 变量落成颜色**（`defaultColor: false` 时 shiki 不写内联色；主题为深色 `tokyo-night` / 浅色 `light-plus`）：`:root[data-pw-theme='dark']` 与 `[data-pw-stage='light'|'dark']` 两套规则都写了，实测 span 颜色 `rgb(30,117,79)` / 暗色 `rgb(77,147,117)` 而不再是继承正文色
21. **预览宽度（仅场景视图，且居中）**：页头是三列网格 `minmax(0,1fr) auto minmax(0,1fr)` —— 左「侧栏开关 + 面包屑」、中「宽度控件」、右「视图切换 / 编辑器 / 主题 / 索引」，宽度控件落在页头**真正的几何中心**（实测 1440 视口页头中心 850、控件中心 850，delta 0；1280 / 1100 / 1000 / 900 下 delta 也都是 0，页头 `scrollWidth === clientWidth`，面包屑不被挤裁）。切到 API 视图时整组宽度控件隐藏、也不再套设备外壳（`.pw-device-wrap` 变 `is-auto`），表格按内容区宽度通栏显示 —— 表格没有「手机 / 平板」的概念，留着一个按不动的尺寸开关只会误导。页头 5 个入口（自适应 / 手机 390 / 平板 820 / 桌面 1280 / 自定义），选非自适应时页面内容装进设备外壳 —— 手机 40px 圆角 + 听筒条、平板 26px 圆角、桌面 12px 圆角 + 三色点标题栏；自定义 320–1920px（实测输入 700 → 外壳切平板、caption `自定义 · 700px`）；宽度存 `rinova-playground:viewport`，刷新后保持；目标宽度超出可用空间时夹住并显示实际宽度（实测桌面 1280 → 1140）
22. **窄宽度响应式**：预览宽度是容器宽度，场景内「输入 | 输出」用 `@container pw-preview (max-width: 760px)` 改单栏（实测手机档 `grid-template-columns` 单列 321px、无横向滚动），页内边距同步收紧到 14px
23. **索引面板外观**：216px 宽，左侧 1px 分隔线与正文分开，内边距 18/14/24；分组标题（概要 / PROPS / EVENTS）与链接文字同在 9px 内缩，组间距 18px；当前项是 6px 圆角的品牌色药丸（左右各留 16px，不再通栏到窗口边缘）；滚动条走统一的 `.pw-scrollbar()`（6px 圆角细条，见第 30 条）
24. **索引可收起**：页头最右侧 `PanelRight*` 按钮切换索引，收起时槽位宽 216 → 0（内容列同时变宽），状态存 `localStorage: rinova-playground:index-open`，刷新后保持；API 视图下按钮隐藏
25. **索引在外壳之外**：右侧场景索引是页面级导航，不装进设备外壳 —— 实测手机档外壳 `260 → 650`、索引 `1240 → 1440`，`index.left > shell.right`；四种宽度下索引都保持可见（旧版手机档会隐藏索引，已改）
26. **侧栏收起入口只有一个**：页头最左侧的 `PanelLeft*` 按钮（品牌条里不再放第二个收起按钮 —— 同一动作两个入口加两条同名 tooltip 只会让人犹豫；而且侧栏收起后品牌条不可见，只有页头按钮还能把它放开）。实测 260 → 0 → 260，状态写 localStorage
27. **浅色/深色切换有动效**：点主题按钮时以按钮坐标为圆心做 420ms 圆形揭开（View Transitions + `clipPath` 动画，`ease` 曲线），动画期间是快照、不可交互；`prefers-reduced-motion: reduce` 或键盘触发（`detail === 0`）时直接切换
28. **窄窗口索引让位**：视口 ≤1080px 时索引槽与右上角开关一起隐藏（实测 1000px：`slot display none`、`button display none`、正文列 686px；1440px：216px / flex / 正文 910px），避免 260px 侧栏 + 216px 索引把正文挤到 300 多像素
29. **侧栏品牌条与页头等高**：两者都是 **49px**（含 1px 底边），横向分隔线在侧栏分界处连续不断开（实测两侧 `bottom` 均为 49px，delta 0）；页头改成固定高度后内容仍垂直居中
30. **全局滚动条统一**：框架自己的 7 个滚动容器（侧栏导航 `.pw-sidebar__nav`、页面滚动区 `.pw-page__scroll`、右侧索引 `.pw-index`、源码面板 `.pw-source__code`、代码块 `.pw-code`、输出面板 `.pw-output__body`、API 表内容区 `.pw-api__body`）统一走 `styles/mixins.less` 的 `.pw-scrollbar()` —— 6px、轨道透明、无步进按钮、圆角胶囊，拇指 `text-muted` 16% → 容器 hover 34% → 拇指 hover 56%；**只写 `::-webkit-scrollbar`**，不再混用 `scrollbar-width` / `scrollbar-color`（Chromium 里标准属性会盖掉 webkit 规则，滚动条变回常驻粗条）。实测这 7 个容器 `offsetWidth - clientWidth` 都是 6px；**演示画布里的组件不受影响**：构建产物里没有任何以 `.pw-scene__canvas` 为前缀的滚动条选择器，画布内滚动容器保持浏览器原生样式

## F2 预览区（v0.3 更新）

**行为**
- 一个页里纵向渲染该页所有场景；每个场景 = 标题（`#锚点` + 「在编辑器打开」）+ 说明 + API 标签 + 预览 + 折叠源码
- 预览懒挂载：视口外只渲染骨架，`IntersectionObserver` 进入 600px 内才挂载真实组件
- 场景错误边界：`onErrorCaptured` 捕获后渲染错误卡片（消息 + 场景文件 + 可展开调用栈），页内其它场景不受影响
- 场景内可用 `<PwDemoGrid>` / `<PwDemo>` 并排多个 Demo，每个 Demo 一套独立的 `useSceneArgs` 槽位；`min` 按最小列宽自动折行，`PwDemo` 支持 `direction` / `align` / `surface`（默认 none，画布已是底）。**纯便利组件，不强制、不做校验拦截**，消费端照样可以自己写布局
- **演示画布自带主题**：预览区是独立的 `[data-pw-stage]` 作用域，重定义 12 个 token + `color-scheme`，默认 `'light'` —— 很多组件库只做浅色，放在暗色外壳里会变成黑底黑字（实测暗色外壳下 MyTable 的斑马纹只给偶数行上色，奇数行直接透出深色页面）；`config.theme.stage: 'auto'` 时跟随外壳

**验收（实测）**
1. 故意 `throw` 的场景显示错误卡片，其余 4 个场景照常渲染，无 Vite 错误遮罩
2. 一页 5 个场景时首屏只挂 2 个实例，滚动到第 5 个才加载
3. 窄屏（<900px）Demo 栅格自动折成单列
4. 暗色外壳 + 浅色组件（`MyTable`）：画布背景 `rgb(255,255,255)`、文字 `rgb(28,32,36)`；把 `data-pw-stage` 改成 `dark` 后变 `rgb(22,24,29)` / `rgb(230,232,236)`

**宽度与视口**
- 页头三档：自适应 / 平板 820px / 手机 420px，作用于正文容器

**边界**
- 场景内的全局样式（非 scoped）不做沙箱隔离（明确不上 iframe / Shadow DOM，见 07）；构建期检查 `<style>` 必须带 `scoped`、禁止 `:root` / `html` / `body`

## F3 代码展示区（v0.3：场景内源码卡片 + Monaco 抽屉）

**本地编辑器选择器**（页头右侧，全局一个）
- 选中结果对全站生效；场景里的「在编辑器打开」在源码卡片头部（每个场景一处，不再占用标题行）
- 下拉：切换编辑器（内置 VS Code / Cursor / Windsurf / Trae / Zed / WebStorm / IDEA / PhpStorm / Sublime / Nova），选择存 `localStorage`，刷新后保持
- 下拉底部「自定义协议…」：填任意 `xxx://file/{file}:{line}` 模板，覆盖没内置的 IDE
- 菜单底部另给「复制文件路径」，编辑器未安装时兜底

**场景内源码卡片**（每个场景底部）
- 头部：折叠箭头 + 文件图标 + 「源码」+ 文件名 + 复制 / 在编辑器打开
- 展开后按 `sources` 出 Tab（场景自身 + `sceneMeta.files`），代码带行号，最高 420px 内部滚动
- 首次展开或切 Tab 才读源码；复制失败时退回 `execCommand`

## F3.1 源码展示（v0.3 改动）

源码只在场景内展示：每个场景下方一行「源码 · 文件名」，点开由 shiki 渲染、可复制、可多文件切 Tab。

**卡片头部动作**（每个场景各一套）

| 按钮 | 行为 |
|---|---|
| 放大镜 | 在源码中搜索（见 F3.1.1） |
| 复制 | 复制**当前 Tab 的源码原文**（卡片折叠时先按需读一次再复制，不需要先展开），图标变 √ 1.5s，toast「已复制 xxx.vue」 |
| 复制路径 | 复制**当前 Tab 文件的绝对路径**（`config.root` + `rel`；没配 root 时退回仓库相对路径），toast 里带出整条路径 —— 与「在编辑器打开」是两个独立按钮，没有 IDE 也照样能复制 |
| 在编辑器打开 | 仅在 `config.root` + `editor.preset` 都有值时出现，用 URL scheme 打开 |

**图标按钮的 tooltip 走统一实现**：文案写在 `data-tip` 上、读屏用 `aria-label`，由 `components/PwTooltip.vue` 用事件委托 + `position: fixed` 渲染气泡（延迟 120ms、跟随滚动与点击消失、不会被 header / 卡片的 overflow 裁掉），不再用浏览器原生 `title`（太慢且样式不跟外壳）。

### F3.1.1 源码内搜索

**入口**
- 源码卡片展开后，头部出现搜索按钮（放大镜）；点击展开搜索行并聚焦输入框
- 卡片内有焦点时 `⌘/Ctrl + F` 打开搜索并 `preventDefault`（不弹浏览器查找）；焦点不在卡片内则不拦截
- `Esc` 关闭并清空高亮

**行为**
- 实时匹配（120ms 防抖）；`Aa` 区分大小写、`W` 全词匹配；`Enter` 下一个、`Shift+Enter` 上一个，首尾循环
- 计数 `1/5`；无结果显示「无结果」；空关键字不显示计数
- 当前匹配实底高亮（`--rp-color-warning` 底色 + `--rp-color-bg` 文字），其余匹配 32% 淡底；跳转时只滚源码容器，不带动整页
- 只搜当前文件：切 Tab 后关键字保留、在新文件里重新匹配并从第一个开始；折叠卡片会清空搜索
- 单文件匹配上限 2000 处，超出不再高亮（防超大文件卡顿）
- 复制源码仍是未高亮的原文（复制取的是 `code` 字符串，不受 DOM 标记影响）

**实现要点**
- shiki 把一行拆成多个 token `<span>`，直接对单个文本节点 `indexOf` 会漏掉跨 token 的词（`:columns`、`'columns'`、`width: 120`）。做法：先把 DOM 文本节点扁平化成一条字符串并记下每个节点的起点 → 在扁平串上匹配 → 按交集映射回节点、节点内**从后往前**切分（切后面的偏移不影响前面的）
- 匹配工具在 `src/code/find.ts`（纯函数，`verify` 直接调它做单测）；`CodeBlock` 新增 `query` / `caseSensitive` / `wholeWord` / `active` 四个可选 props 与 `count` 事件，不传时行为与之前完全一致

**验收（实测）**
1. `basic.vue` 搜 `columns` → 计数 `1/5`，`<mark>` 5 个，与原文出现次数一致；`Enter` 到 `2/5`，`Shift+Enter` 从 `1/5` 环回到 `5/5`（容器 `scrollTop` 272）
2. 搜 `Column`（忽略大小写）7 处；开 `Aa` 后 2 处
3. 搜 `col` 命中 7 处；开 `W` 后「无结果」
4. 跨 token：`:columns` / `columns=` / `'columns'` / `width: 120` 均命中 1 处（DOM 里分别是 2~3 个 `<mark>` 片段）
5. 多文件：`multi.vue` 6 处 → 切到 `MyButton.vue` 4 处，关键字保留
6. 卡片内按 `⌘F`：事件 `defaultPrevented=true`，光标落在搜索框；`Esc` 后搜索行消失、`<mark>` 归零

## F8 契约清单 manifest（M3，已实现）

**行为**

## F10 API 文档表（M7，已实现）

**行为**
- 页头「场景 / API」切换；API 视图只在该页绑定了组件时出现（`pageMeta.component` 或目录名同名匹配）；API 视图不提供尺寸能力（宽度控件隐藏、不套设备外壳），索引面板与场景相关的入口一并隐藏
- API 视图用 flex 分栏：页签行（组件名 + Props/Events/Slots/Exposes/Types）`flex: 0 0 auto` 固定，内容区 `.pw-api__body` 用 `flex: 1; min-height: 0; overflow: auto` 自己滚，滚动条只属于内容区；同时 `.pw-page__scroll.is-api` 改成 `overflow: hidden; padding: 0`，避免外层再滚一次（用 sticky 会贴不住：外层 padding 会让它停在内容盒顶端、上方缝隙透出滚动内容）
- 表头四组 Tab：Props / Events / Slots / Exposes，数字为条目数；契约里引用了具名类型时多一个 Types Tab；标题右侧给「共 N 个 API · M 个缺说明」
- 列：名称（必填徽标）、类型（点击复制；引用了具名类型时点击跳到 Types Tab）、默认值、说明、演示（列出引用该 API 的场景，点击跳过去）
- Events 的类型列显示参数列表 `[event: FocusEvent]`，下一行给完整签名
- 空值统一用虚线胶囊（标签形式）：默认值空 → `—`、类型空 → `—`、说明空 → `缺说明`（悬停提示「补 JSDoc 就会显示在这里」）、演示空 → `无`；不用裸文字或裸破折号
- 默认值列：对象 / 数组按原文单行展示（列宽 32%，不用多行折行），超过 420px 才省略号截断，悬停给完整值；Props 表里类型列让到 24%，其它 Tab 回到 32%
- 点场景标题下的 API 标签 → 切到 API 视图并高亮对应行

**数据来源**：`vue-component-meta` 读 TS 类型与 JSDoc，构建期注入 `virtual:playground/api`（只含被页面引用的组件），运行时零请求。

**类型定义**：`manifest.components[].types` 是契约引用到的具名 `interface` / `type`（声明原文 + 来源文件，含 JSDoc），Types Tab 里逐块高亮展示；不做字段展开表，成员说明与默认值写在接口的 JSDoc 里。`Record<...>` 之类没有具名字段的类型不出现。

**已知限制**：事件的 JSDoc 无法提取，用 `pageMeta.apiNotes` 补。

**验收（实测）**

5. 插件上下文 `ctx`：`app` / `config` / `globals` / `scenes` / `get(name)` / `wrap(component, props?)` / `ui.header | sidebarFooter | panel`。
6. 插件串行初始化；单个失败默认整页错误卡片（含插件名 + 路径 + 消息），`optional: true` 时跳过。
7. 场景取用：`usePlaygroundEnv()`（`globals` 打底 + 插件返回值按声明顺序合并）、`usePlaygroundPlugin(name)`（单个插件）、`usePlaygroundTheme()`（供插件 UI 跟随明暗）。
8. `ctx.wrap()` 只包**演示画布内的场景内容**，不包外壳：第三方 config provider 不影响侧栏 / 索引 / 页签。
9. 三个 UI 缝位固定尺寸（见 02 §3.9.2），各自套错误边界；`ui.panel` 同一时刻只开一个，Esc / 遮罩点击关闭并把焦点还给触发元素。

**边界（明确不做）**

- 不内置 auth / env / mock 的实现 —— 只给协议与测试床示例
- 不远程加载插件、不做插件市场
- 不做场景级 / 页面级插件开关
- 不提供构建期插件钩子（消费端自己的 `vite.config` 本来就能加）
- 插件提供的是应用级单例，一个场景改 pinia 会影响其它场景；要隔离只能上 iframe，而沙箱已在 07 §7 否决
- 不做插件 HMR 保状态，改插件文件即 full-reload

## F12 非组件模块 API（v0.5）

**行为**

1. `config.modules` 声明模块 glob（如 `src/lib/**/*.ts`）。不配时**完全不建第二个 TS Program**，行为与之前一致。
2. 用 TypeScript 编译器 API 抽取每个文件的导出：函数 / hooks（`use` + 大写）、常量、`interface` / `type`。
   - 函数：`name` / `kind` / `signature` / `params[{name,type,optional,default,description}]` / `returns` / `description`
   - 参数说明取 JSDoc `@param` 或参数上方的 `/** */`；默认值取源码原文（`= {}` → `{}`）；有默认值的参数标为可选
   - 常量：`type` + 短值原文（≤ 80 字符）+ 说明；对象字面量过长时留空，交给类型
   - 类型：声明原文（`node.getText`），带字段级 JSDoc
3. 页 → 模块绑定：`pageMeta.module` 优先，其次按页目录名同名匹配（与组件绑定同一规则）。
4. API 视图新增「函数 / 常量 / 类型」三张表，**与组件 API 表共用 `styles/api.less` 与 `.pw-api*` 结构**（同一套页头、页签、表格列、空值胶囊、类型可点跳转、场景可点跳转）：函数表列为「名称（含签名整行）/ 参数 / 返回 / 说明 / 场景」，常量表为「名称 / 类型 / 值 / 说明 / 场景」；类型页与组件 Types 页同一张卡片。
5. 契约写进 `.playground/manifest.json` 的 `modules[]` 与 `llms.txt`（函数签名 + 参数 + 常量），`pageModules` 走 `virtual:playground/api`，运行时零请求。
6. 覆盖判定与组件同一启发式：导出名出现在任一场景源码里即算覆盖。

**边界**

- 只取**第一个调用签名**：重载函数只展示一个，不做重载列表
- 不解析 class / 装饰器 / 默认导出
- 解构参数在 TS 里名字是 `__0`，统一显示为 `options`
- 模块清单的 Program 按「tsconfig + 模块文件 mtime/size」缓存；改**被引用的其它 .ts** 不会自动失效（与组件契约同一已知限制）
- 大项目启用 `modules` 会多建一次 Program（组件那套 checker 不能复用）：成本按项目规模，不配则零成本
