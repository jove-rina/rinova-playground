# 02 核心概念

设计原则：**场景作者面对的概念只有 3 个**。任何新能力都必须能被归入这三个之一，否则不进主线。

集成者（把 playground 接进自己项目的人）另有 §3.9 的两个可选字段（`globals` / `plugins`），它们不出现在场景作者的视野里。

## 1. `playground.config.ts` — 唯一配置文件

```ts
import { defineConfig } from '@rinova/playground'

export default defineConfig({
  title: 'My Lib',
  scenes: 'src/scenes',
  sources: true,
  theme: { ui: 'auto', stage: 'light' },
})
```

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `title` | `string` | 包名 | 顶部品牌区标题 |
| `scenes` | `string` | `'src/scenes'` | 场景扫描根目录（相对项目根） |
| `sources` | `boolean` | `true` | 是否展示每个场景下方的源码行 |
| `theme.ui` | `'light' \| 'dark' \| 'auto'` | `'auto'` | 外壳主题，落到 12 个 CSS 变量 |
| `theme.stage` | `'light' \| 'dark' \| 'auto'` | `'light'` | 演示画布主题，独立于外壳；组件库只有浅色时不要改成 `auto` |
| `exclude` | `string[]` | `[]` | 扫描时排除的 glob |
| `base` | `string` | `'/'` | 部署子路径 |
| `port` | `number` | `5273` | dev server 端口 |
| `components` | `string[]` | — | 契约清单要扫描的组件 glob（如 `src/components/**/*.vue`）；不配则不生成 manifest |
| `modules` | `string[]` | — | 非组件模块 glob（如 `src/lib/**/*.ts`）：抽函数 / hooks / 常量的契约，进 API 页签与 manifest；不配则完全不建第二个 TS Program |
| `tsconfig` | `string` | `tsconfig.json` | 组件契约提取用的 tsconfig |
| `globals` | `Record<string, unknown>` | — | 供 demo 读取的纯常量（明文进 bundle，禁止放 token / 密钥）；合并规则见 §3.9 |
| `plugins` | `string[]` | `[]` | 运行时插件模块路径（相对项目根 / `/src/...` / `@/...`）；协议见 §3.9 |

约束：**配置文件是唯一的配置入口**。任何"再加一个 xxx.config.ts"的提案默认否掉。

## 2. `scenes/<分组>/<页>/<场景>.vue|md` — 三级目录（子组件再深一层）

规则（全部可预测，不看文档也能猜对）：

| 规则 | 行为 |
|---|---|
| 目录结构 | `scenes/<分组>/<组件页>/<场景>.vue` 是**三层**；组件有子组件时，子组件页 = `scenes/<分组>/<组件页>/<子组件页>/<场景>.vue`（四层）。分组下不能直接放 `.vue` |
| 侧栏 | 两级：**分组 → 组件页**（页名后跟场景数）；点页进入正文 |
| 页内 | 该页所有场景纵向排开，右侧是 `概要 / Props / Events / Exposes / Slots` 索引，滚动高亮、`#场景名` 可分享 |
| 文件名 | kebab-case 文件名自动转标题（`size-large.vue` → `Size Large`）；中文文件名保持原样 |
| 排序 | 页内**先按 `section` 分组**（概要 → Props → Events → Exposes → Slots，与右侧索引同序），组内按 `sceneMeta.order` 升序、同值按文件名；**组内**页与页之间用 `<页>/meta.ts` 的 `order`（同值按页目录名）；**分组顺序 = `config.groups` 的声明顺序**，没登记的组排在最后（按目录名字母序） |
| 一组多页 | 一个分组下可以有任意多个组件页（目录就是页，各自有 `meta.ts`），页可以指向同一个组件、也可以指向不同组件（`pageMeta.component`）；路由 `/<分组>/<组件页>` 天然区分 |
| 内容页 | 页可以不绑定组件：`meta.ts` 里不写 `component` 就只渲染场景内容，右上角不出现 API 页签（示例：minimal-lib 的「介绍」分组，`intro/overview`、`intro/conventions`） |
| 非组件文件 | 函数 / hook / 常量同样能进文档：`meta.ts` 不写 `component`，写 `module: 'money'` 绑定 `config.modules` 里的文件；场景里 `import` **真实源码**，参数用 `useSceneArgs` 喂、返回值用 `useSceneOutput` 出，`sceneMeta.files` 把实现贴进源码卡片。签名 / 参数 / 返回值 / 常量 / 类型由 TypeScript 编译器 API **自动提取**，进 API 页签的「函数 / 常量 / 类型」三张表（示例：minimal-lib 的「工具与函数」分组） |
| 子组件 | 组件页目录下再放子目录就是子组件页（自带 `meta.ts` 与场景），侧栏显示为「组件 → 子组件」二级；父页可以没有自己的场景，只要子页有就会保留；路由 `/<分组>/<组件页>/<子组件页>` |
| 折叠 | 侧栏整体可收起（页头按钮，状态存 localStorage）；分组标题可点开收起，**默认只展开当前页所在的分组**；带子组件的组件页有自己的展开箭头，默认收起，进入子页时自动展开 |
| 内容 | 场景可以是 `.vue`（普通 SFC，不要求任何 playground API），也可以是 `.md`（Markdown 内容页） |
| Markdown | `.md` 场景在构建期被包装成组件，运行期用 `marked` + `shiki` 渲染；标题 / 排序 / 标签写在文件头 `---` 里，正文支持 `::: tip/info/warn/danger 标题` 与 `::: steps` 两种容器（渲染成 `PwCallout` / `PwSteps`，和手写 Vue 内容页用同一套组件与样式） |
| 文档场景 | `doc: true`（Markdown 场景自动为 true）时这一页按文档排版渲染：不套演示画布的白卡片，场景标题 18px 充当 h1，正文宽度 720px |
| 源码 | 每个场景下方折叠「源码 · 文件名」，多文件按 `sources` 出 Tab；展开后可搜当前文件（`⌘F` / 放大镜，支持大小写与全词）；没有另外的代码抽屉。**是否展示按「场景 `showSource` > 页 `pageMeta.showSource` > 全局 `sources`」合并，Markdown 场景默认不展示** |
| 隔离 | 一页内的场景各自独立实例；每页错开挂载（视口外只渲染骨架）；一个场景抛错只替换该块，整页继续可用 |

用户写一个场景的全部代码：

```vue
<!-- src/scenes/button/button/size.vue -->
<script setup lang="ts">
import { ref } from 'vue'
import { MyButton } from '@my/lib'
const size = ref('large')
</script>

<template>
  <MyButton :size="size">Button</MyButton>
</template>
```

侧栏立刻出现「Button / Button」，正文里出现「Size」一节。**没有第二步。**

## 3. `sceneMeta` — 可选，只在需要元信息时写

不写也能用；需要标题覆盖、输入/输出面板、额外文件时才写。

```vue
<script lang="ts">
import { defineSceneMeta } from '@rinova/playground'

export const sceneMeta = defineSceneMeta({
  title: '尺寸 · 大号',
  order: 2,
  tags: ['size', 'props'],
  description: '同一按钮在 size=large 下的表现',
  payload: {
    input: () => ({ size }),
    output: () => ({ clicked: clickCount.value }),
  },
  files: ['src/components/Button/Button.vue'],
})
</script>
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | 否 | 覆盖文件名推导出的标题 |
| `order` | 否 | 同层排序权重，小在前（只在同一 `section` 内比较） |
| `tags` | 否 | 用于搜索与筛选 |
| `description` | 否 | 场景说明，显示在预览区上方 |
| `files` | 否 | 额外要展示的源码文件（相对项目根） |
| `hideInNav` | 否 | 不进页内索引与侧栏计数，但 `#场景名` 直达可用 |
| `section` | 否 | 页内索引分组：`overview`（默认）/ `props` / `events` / `exposes` / `slots` |
| `api` | 否 | 本场景覆盖的公开 API 名，如 `['disabled']`，显示在标题下方 |

**解析方式**：`@rinova/playground-vite` 在扫描阶段用 `@vue/compiler-sfc` 取出非 `<script setup>` 的 `<script>` 块，交给 jiti 执行，只把可序列化的导航字段（`title` / `order` / `tags` / `description` / `hideInNav`）注入虚拟模块；`payload` 里的函数留在运行时，不进 manifest。

- 排序：先按 `section` 分组序（`overview` → `props` → `events` → `exposes` → `slots`，未声明按 `props`），组内按 `order` 升序、未写排在最后，再按路径 —— **正文顺序与右侧索引分组必须一致**，两处共用 `scene-order.ts` 的同一个比较器
- `hideInNav: true` 的场景不进侧栏、不计入底部场景数，但 URL 直达仍然可用
- 解析失败（例如 `title: someVar` 这种运行时表达式）会在 dev 控制台告警并回退到文件名推导，不阻塞页面

## 3.5 输入 / 输出：`useSceneArgs` + `useSceneOutput`

`sceneMeta` 在构建期执行，拿不到场景组件内部的状态，所以运行时的输入/输出另开两个入口。表单会**渲染在场景内部**（预览下方，左侧参数、右侧输出），输出是常显面板，页头没有全局开关：

```vue
<script setup lang="ts">
import { useSceneArgs, useSceneOutput } from '@rinova/playground'

const count = ref(0)

// 输入：面板渲染成表单，改了这里组件立刻重渲染
const args = useSceneArgs(
  { label: '点我 +1', size: 'md' as 'sm' | 'md' | 'lg', disabled: false },
  { options: { size: ['sm', 'md', 'lg'] }, labels: { label: '文案', size: '尺寸', disabled: '禁用' } }
)

// 输出：面板每 400ms 取一次快照
useSceneOutput(() => ({ clicked: count.value }))
</script>

<template>
  <MyButton :size="args.size" :disabled="args.disabled">{{ args.label }}</MyButton>
</template>
```

**表单控件按值的类型自动选择**：

| 值类型 | 控件 |
|---|---|
| `boolean` | 开关（`PwSwitch`） |
| `number` | 数字输入 |
| `string` | 文本输入 |
| `string` + `options[key]` 提供可选值 | 下拉框 |

- 全部是客户端响应式，**生产环境的静态站同样可用**（不依赖 dev server）
- 只有声明了 `useSceneArgs` / `useSceneOutput` 的场景才渲染参数区，没声明的场景没有这块 UI
- 场景卸载自动反注册，不会串到下一个场景

**一个场景多个 demo**：各自声明一次，并在选项/第二个参数里写槽位名，面板按槽位分块，互不影响：

```ts
const primary = useSceneArgs({ label: '主按钮' }, { slot: '主按钮' })
const ghost = useSceneArgs({ label: '次按钮' }, { slot: '次按钮' })
useSceneOutput(() => ({ clicked: primaryCount.value }), '主按钮')
useSceneOutput(() => ({ clicked: ghostCount.value }), '次按钮')
```

槽位顺序 = 代码里的声明顺序；只有一块时不显示槽位标题。

## 3.6 分组、页说明与本地 IDE

```ts
export default defineConfig({
  groups: { form: '表单', display: '展示' },
  editor: { preset: 'vscode' },
})
```

- `groups`：目录名 → 侧栏分组名；**对象里声明的顺序就是侧栏顺序**，没声明的排后面
- 页的标题与说明写在 `<页>/meta.ts`：

```ts
import { definePageMeta } from '@rinova/playground'

export const pageMeta = definePageMeta({
  title: 'Input',
  description: '输入框：受控、禁用、前后缀。',
  order: 1,
  // 这一页演示哪个组件 → 页头会出现「API」视图（不写则按目录名同名匹配）
  component: 'MyInput',
  // API 表的补充说明，补 JSDoc 覆盖不到的地方（当前事件说明无法从 defineEmits 提取）
  apiNotes: { 'events:enter': '按下回车，参数是当前值' },
  // 内容页：不展示场景源码（Markdown 场景默认就是 false）
  showSource: false,
  // 内容页：按文档排版渲染，不套演示画布
  doc: true,
})
```

- `showSource` / `doc` 只对内容页有意义；组件页保持演示画布 + 源码卡片
- 不绑组件的页要在 `meta.ts` 里显式写 `showSource: false`（`pnpm verify` 会检查，防止介绍页又挂一条源码）

- `editor.preset`（`vscode` / `cursor` / `webstorm` / `custom`）：场景标题右侧出现「在 Cursor 打开」按钮，用 URL scheme 直达本机文件的对应行；静态产物同样可用（插件把项目根注入配置）。**preset 必须和本机安装的编辑器一致**——装了 Cursor 却写 `vscode` 会点了没反应（系统里没有 `vscode://` 处理器）

```ts
editor: {
  preset: 'cursor',                       // 默认值
  options: ['cursor', 'vscode'],          // 可选：给访问者的候选列表
  allowChoice: true,                      // 默认 true，按钮右侧出现下拉
  exposeRoot: true,                       // 对外发布设 false → 降级为「复制路径」
}
```

- **访问者可以自己选**：页头右侧的编辑器图标（全局一个，不占每个场景），点开菜单选择，写到 `localStorage` 的 `rinova-playground:editor`，刷新后仍然生效；配置里的 `preset` 只是默认值
- **内置协议**（都是各编辑器官方注册的 scheme）：`vscode` / `cursor` / `windsurf` / `trae` / `zed` / `webstorm` / `idea` / `phpstorm` / `sublime` / `nova`
- **任意其他 IDE**：菜单底部「自定义协议…」可直接填模板，例如 `trae://file/{file}:{line}`；占位符 `{file}`（绝对路径）、`{fileEnc}`（URL 编码）、`{line}`（行号）。同样存 localStorage，只影响填的人
- `allowChoice: false` 锁定成配置指定的编辑器；`allowCustom: false` 关掉自定义入口；`options` 只有一个且不许自定义时下拉自动隐藏

### 3.6.1 Markdown 场景

页面目录下的 `.md` 直接就是场景，不用写 `<script>`：

```md
---
title: 键盘操作
order: 2
tags: [快捷键]
description: 导航和搜索都能只用键盘走完。
---

正文按 Markdown 写；下面两种容器会渲染成公共组件。
```

| 容器 | 渲染 | 语气 |
|---|---|---|
| `::: tip 标题` / `info` / `warn` / `danger` | `PwCallout` | 建议 / 说明 / 注意 / 危险 |
| `::: steps` + 有序列表 | `PwSteps` + `PwStep` | 带序号的步骤 |

- 代码块按语言自动高亮（已注册 `vue` / `ts` / `js` / `css` / `less` / `html` / `json` / `bash` / `markdown` / `yaml` / `diff`），左上角显示语言角标，**悬停右上角出现「复制」按钮**（复制的是原始代码，不含高亮标签）
- 手写 Vue 内容页里的 `<pre>` 也能拿到同一套：写 `<pre data-lang="ts"><code>…</code></pre>` 或 `<code class="language-ts">`，高亮与复制按钮由 `PwProse` 自动补上
- `.md` 场景默认「不展示源码、按文档排版」；要展示就用 frontmatter 的 `showSource: true`
- 手写内容页（`.vue`）可以用同一套公共组件：`PwProse` / `PwCallout` / `PwSteps` / `PwStep`，视觉与 Markdown 一致

## 3.7 一场景多 Demo

一个场景要并排对比时，用框架导出的布局原语（纯便利组件，不用也能自己写，没有校验拦你）：

```vue
<script setup lang="ts">
import { PwDemoGrid, PwDemo, useSceneArgs } from '@rinova/playground'
const on = useSceneArgs({ size: 'md' }, { slot: '开启' })
const off = useSceneArgs({ size: 'md' }, { slot: '关闭' })
</script>

<template>
  <!-- min：每列最小宽度，放不下自动折行；也可用 columns="2" 固定列数 -->
  <PwDemoGrid :min="240">
    <PwDemo title="disabled = false">
      <MyButton :size="on.size">可点</MyButton>
    </PwDemo>
    <PwDemo title="disabled = true" direction="column" surface="card">
      <MyButton :size="off.size" disabled>不可点</MyButton>
      <template #note>卡片的底色来自 --rp-color-surface</template>
    </PwDemo>
  </PwDemoGrid>
</template>
```

| 原语 | 作用 | 常用 props |
|---|---|---|
| `PwDemoGrid` | Demo 排版容器 | `columns: 1–4`、`min: number`（优先于 columns，自动折行）、`gap: 'sm' \| 'md' \| 'lg'` |
| `PwDemo` | 单个 Demo 块：标题 + 控件区 + `#note` / `#footer` | `title`、`direction: 'row' \| 'column'`、`align: 'start' \| 'center' \| 'end'`、`surface: 'none' \| 'card'`（默认 none，画布已经是底） |
| `PwSceneNote` | 场景内引用样式说明块 | `text` 或默认插槽 |
| `PwApiBrief` | 场景标题下的 API 胶囊（框架自动渲染） | — |

`useSceneArgs` / `useSceneOutput` 的 `slot` 决定检查器面板里的分块名。

## 3.8 预览宽度（设备外壳）

页头右侧是预览宽度切换，值存 `rinova-playground:viewport`，刷新后保持：

| 档位 | 宽度 | 外壳 |
|---|---|---|
| 自适应（默认） | 铺满可用空间 | 无，就是普通文档流 |
| 手机 | 390px（iPhone 14/15 逻辑宽） | 手机：40px 圆角 + 听筒条 |
| 平板 | 820px（iPad Air 竖屏） | 平板：26px 圆角 |
| 桌面 | 1280px（笔记本基准） | 桌面窗口：12px 圆角 + 三色点标题栏 |
| 自定义 | 320–1920px，回车 / 失焦生效 | 按宽度自动挑外壳（<640 手机、<1024 平板、其余桌面） |

- 宽度是**容器宽度**，不是浏览器窗口宽度，所以内部的响应式判断用 **container query**（`.pw-device` 是 `container-name: pw-preview`，场景里的输入/输出面板在 `max-width: 760px` 时改单栏）
- 右侧「概要 / Props / Events …」是页面级导航，**在设备外壳之外**，不随预览宽度缩放（外壳只包住内容）
- 外壳宽度超过可用空间时会被夹住，底部 caption 显示**实际渲染宽度**（`手机 390px` / `自定义 · 700px`）

## 3.9 集成能力：`globals` 与 `plugins`（v0.5）

框架只提供**挂载点**，不内置 auth / env / mock 的实现。消费端的需求与落点一一对应：

| 需求 | 落点 |
|---|---|
| apiBase、环境标识、mock 开关这类纯常量 | `config.globals`（可序列化，零代码） |
| 登录态、当前用户、权限点、业务字典 | 插件的 `setup()` 返回值 |
| pinia / i18n / 全局组件 / 全局指令 / 请求层 | `ctx.app`（真实的 `App` 实例） |
| el-config-provider、router 这类必须包裹 demo 才生效的 provider | `ctx.wrap()` |
| 外壳里的「当前用户 / 环境切换 / 请求日志」 | `ctx.ui` 的三个缝位（§3.9.2） |

### 3.9.1 声明方式：模块路径，不是内联对象

`virtual:playground/config` 是 `JSON.stringify(config)` 生成的，**函数传不过去**。所以插件只能声明路径：

```ts
export default defineConfig({
  globals: { apiBase: '/api', appName: 'ERP' },   // 明文进 bundle，禁止放 token / 密钥
  plugins: ['./src/playground/plugins.ts'],       // 相对项目根；也接受 /src/... 与 @/...
})
```

```ts
// src/playground/plugins.ts
import { definePlaygroundPlugin } from '@rinova/playground'

export default [
  definePlaygroundPlugin({
    name: 'auth',
    async setup(ctx) {
      const user = await fetch(`${ctx.globals.apiBase}/me`).then((r) => r.json())
      return { user }                     // → usePlaygroundPlugin('auth').user
    },
  }),
]
```

场景里取用（两种，后者不需要学框架 API）：

```ts
const env = usePlaygroundEnv<{ apiBase: string; appName: string }>()  // globals + 所有插件返回值浅合并
const auth = usePlaygroundPlugin<{ user: User }>('auth')               // 单个插件
// 或者插件里 ctx.app.provide(MyKey, value)，场景里原生 inject(MyKey)
```

规则（全部写死，不留解释空间）：

- 插件按数组顺序**串行** `await setup()`，后一个可以 `ctx.get('auth')` 读前一个的返回值
- `setup()` 抛错默认**整页报错卡片**（含插件名与路径）—— 登录态没拿到还继续渲染，每个场景都会报一堆假错；标 `optional: true` 的插件失败只 `console.warn` 并跳过
- 插件是**应用级**的：没有场景级开关，也不按页面启用
- 改插件文件 = full-reload，插件状态重置（不做 HMR 保状态）
- `globals` 与插件的合并顺序：`config.globals` 在最底层，插件按声明顺序覆盖

### 3.9.2 UI 缝位：三个固定位置，不是插件画布

| 缝位 | 位置 | 尺寸上限 | 典型用途 |
|---|---|---|---|
| `ui.header` | 页头右侧、预览宽度控件之前 | 单个 220px，高 28px（不改变 49px 页头） | 当前用户、环境切换、日志开关 |
| `ui.sidebarFooter` | 侧栏底部、「N 个页面 · M 个场景」上方 | 228px 宽（260−16×2）、64px 高 | 登录态卡片、环境/版本标识 |
| `ui.panel` | 右侧抽屉，通高 420px，同时只开一个 | Esc / 遮罩点击关闭，焦点回到触发按钮 | 请求日志、环境变量查看器、权限模拟 |

```ts
setup(ctx) {
  ctx.ui.header({ component: AccountMenu, props: { user } })
  ctx.ui.sidebarFooter({ component: EnvBadge })
  const panel = ctx.ui.panel({ id: 'requests', title: '请求日志', component: RequestLog })
  // 插件自己的 UI 组件里也可以 usePlaygroundUi().togglePanel('requests')
}
```

**不做**（这些都是把外壳变成插件画布的入口）：插件加页面 / 路由、插件替换正文区域、插件改框架样式、插件往场景卡片里插内容。要一个「环境说明」就写 `.md` 场景，要一个「请求日志」就开抽屉。

**插件 UI 的样式不归框架管**：可以用任何 UI 库（D2 只约束框架自身，`verify` 的「无 UI 库依赖」只扫 `packages/`）。但暗色外壳下必须自己跟随主题 —— 框架只提供 `usePlaygroundTheme()`（`ComputedRef<'light' | 'dark'>`）与 12 个 `--rp-*` 变量，不替第三方库切 `dark` class。这是插件 UI 最容易翻车的地方。

**错误隔离**：每个缝位外面套错误边界，插件 UI 抛错只替换那一块，外壳继续可用（复用场景错误卡片的实现，必要时抽成通用 `PwErrorBoundary`）。

## 3.10 AI 能力面：环境清单、llms.txt 与 MCP（v0.7 起，v0.8 拆文件与加预算）

框架把「这个演示站有什么、怎么写新场景」变成可读数据，AI 不需要读源码就能动手。三块数据同源：`.playground/manifest.json`（机器读）、`.playground/llms.txt`（模型读）、MCP 工具（交互读）。

### 3.10.1 manifest 的 `env` 段

`env` 与组件契约一起生成，场景增删改后 **400ms 防抖重算**（dev），build 时写进 `dist/`：

```json
{
  "title": "Minimal Lib",
  "sceneRoot": "src/scenes",
  "routeBase": "/",
  "groups": [{ "dir": "button", "label": "Button" }],
  "globals": { "apiBase": "/api", "appName": "Minimal Lib" },
  "plugins": ["./src/playground/plugins.ts"],
  "theme": { "ui": "auto", "stage": "light" },
  "sources": true,
  "components": { "configured": true, "count": 7 },
  "modules": { "configured": true, "count": 3 },
  "pages": [
    {
      "id": "button/button",
      "group": "Button",
      "groupDir": "button",
      "title": "Button",
      "order": 1,

```

只放**可序列化**的东西：插件是模块路径（执行结果在运行时才有），`globals` 本来就是纯常量。

### 3.10.2 `llms.txt` 是手册，契约与待办另放两个文件（v0.8）

v0.5 及以前只有组件 / 模块契约；v0.7 把它们塞进同一份手册；**v0.8 起拆三份**（真实宿主 406 个组件时，合并版是 644KB ≈ 29 万 token，模型读不动）：

| 文件 | 内容 | 体量（minimal-lib / df-erp） |
|---|---|---|
| `llms.txt` | 手册 5 节：环境 → 写作规则 → 最小骨架 → 页面清单 → 契约与待办在哪 | 8KB / 8KB |
| `llms-components.txt` | 组件 props/events/slots/exposed/types + 模块函数/常量/类型 | 7KB / 542KB |
| `llms-todo.txt` | 没有场景的 props、没有 JSDoc 的 API、没有场景的模块导出 | 0.3KB / 264KB |

照手册写场景不需要读后两份；要某个组件的契约就调 MCP 的 `capability_get`，不要整份读文件。

**对象 prop 的字段展开有三条规则（v0.8）**，否则一个继承外部大类型的组件就能把清单撑到几 MB：

| 规则 | 判据 | 为什么 |
|---|---|---|
| 外部声明不展开 | 字段声明文件在 `node_modules` 或 `lib.*.d.ts` | 那些文档属于那个库（如 element-plus 的 `TableProps` → csstype 的 1348 个 CSS 字段），不属于宿主 API |
| 单 prop 最多 32 个 | 按声明序截断，写 `fieldCount` + `fieldsTruncated` | 组件真有几百个字段时，全量列出来也没人看 |
| 说明剥表格 + 截 160 字 | Markdown 表格行与 `Baseline…` 段落整行丢弃 | 浏览器支持表是 MDN 文档，不是宿主的 API 说明 |

`llms*.txt` 与 `manifest.json` 都是生成物，**不要手改**；口径变就改生成器（`packages/playground-vite/src/manifest.ts` 的 `renderLlmsTxt` / `renderLlmsComponents` / `renderLlmsTodo`）并同步 `verify` 的断言。

### 3.10.3 MCP 八个工具

响应有预算：单个 prop 的字段超过 8 个时只给一行「共 N 个字段」，细节用 `fields_of` 取；`coverage_report` 默认只给按组件的汇总。

| 工具 | 作用 | 写盘 |
|---|---|---|
| `capability_search` / `capability_get` | 搜组件、取完整契约（组件路径带行号，每个成员带 `← L<n>`） | 否 |
| `fields_of` | 按需取某个 prop / 事件参数的字段（默认前 20 个） | 否 |
| `env_get` | 环境段的人读版：globals / 插件 / 分组 / 页面表 | 否 |
| `scene_scaffold` | 按环境规则算出该建的文件路径与内容（相对 import、sceneMeta、页 meta），**返回文本不落盘** | 否 |
| `scene_validate` | 校验目录层级、样式 scoped、全局选择器、废弃 API、sceneMeta 字段、页绑定；`path` 单项、不传全量 | 否 |
| `scenario_list` | 场景列表（可按组件过滤） | 否 |
| `coverage_report` | 覆盖汇总；`detail=true` 才逐条列出未覆盖的 props | 否 |

写文件永远交给客户端自己的文件工具（docs/03 F9 的决策不变）：MCP 只保证「算得对、校验得快」，不引入注册 API、不做 `capability.try` 那种无头浏览器验证。

**消费端零配置**：不传参数时按进程当前目录找 `.playground/manifest.json`，找不到向上找 6 层（客户端常从包子目录启动）；`--project` / `--manifest` 只在 monorepo 多包或服务从别处启动时才需要。清单是构建产物，工具调用前会比对 `mtime + size`，变了就重读 —— 写完场景不需要重启 MCP 会话。

### 3.10.4 闭环

```
env_get / capability_search
      ↓  选组件 + 选页面
capability_get（契约：类型、默认值、事件参数）
      ↓
scene_scaffold（路径 + 骨架）
      ↓  客户端写文件
dev server 热更新（清单 400ms 内重算）
      ↓
scene_validate（path=新文件）→ 覆盖报告变化
```

实测：新场景写入后清单 **608ms** 刷新，`scene_validate` 对好场景 0 问题、对坏场景命中 `style-scoped` / `style-global` / `deprecated-api` / `scene-meta-field` / `page-component` 五条规则。

## 4. 加载与路由模型

- **扫描**：`@rinova/playground-vite` 在构建期与 dev 期扫描 `scenes` 目录，生成虚拟模块（场景 id + 懒加载 import + 源码 raw）
- **路由**：`/<分组>/<组件页>` 走 History API（`pushState` / `popstate`），页内场景用 `#场景名` 锚点，不依赖 `vue-router`。部署到静态托管时需把未匹配路径 rewrite 到 `index.html`（`vite dev` 与 `vite preview` 已内置该回退）
- **滚动**：页内滚动时右侧索引自动高亮；点索引会先挂载目标场景再滚动（懒挂载会改高度，否则落点会偏）
- **懒加载**：场景组件、源码行、契约清单三者都是独立 chunk；首屏只加载外壳 + 侧栏 + 当前场景
- **HMR**：新增/删除/重命名场景文件无需重启 dev server，侧栏热更新
