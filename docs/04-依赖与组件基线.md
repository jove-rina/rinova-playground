# 04 依赖与组件基线

## 1. 原则

1. **不引入任何 UI 组件库**（Element Plus / Naive / Ant / Vuetify 一律禁止），playground 自带基础通用组件
2. **依赖白名单制**：新增运行时依赖必须在本文档登记并写明理由，否则不进主干
3. **运行时依赖尽量为 peer 或可 tree-shake**；构建期依赖不下发到产物
4. **版本全部锁定**（`pnpm` lockfile + 精确版本号），框架不能靠"上游小版本不破坏"的假设活着

## 2. 依赖白名单

### 运行时（`@rinova/playground` 的依赖）

| 依赖 | 版本 | 用途 | 说明 |
|---|---|---|---|
| `vue` | peer `^3.5` | 框架本身 | 不打包，由用户提供 |
| `shiki` | `4.6.0` | 代码高亮（静态块 + 编辑器） | 细粒度 bundle，按需 `langs` / `themes` |
| `@shikijs/monaco` | `4.6.0` | 把 shiki 高亮接进 Monaco | 与 shiki 同一版本线 |
| `monaco-editor` | `0.57.0` | 代码编辑器 | 仅编辑器 chunk，懒加载 |
| `@lucide/vue` | `1.66.0` | 图标 | 按需 import，单图标 1~2KB |

### 构建期（`@rinova/playground-vite`，不进产物）

| 依赖 | 版本 | 用途 |
|---|---|---|
| `vite` | peer `^8` | 插件宿主 |
| `@vitejs/plugin-vue` | peer `^6` | 用户项目已具备 |
| `vue-component-meta` | `3.3.14` | 契约提取（props / emits / slots / exposed） | 已实测与 TS 5.9.3 兼容 |
| `@modelcontextprotocol/sdk` | `1.32.2` | `@rinova/playground-mcp` 的 stdio server | 仅 MCP 包依赖 |
| `zod` | `4.6.7` | MCP 工具入参 schema | 与 SDK 的 `^3.25 \|\| ^4.0` 兼容 |
| `zod` | `4.6.x` | manifest 校验 |
| `less` | `4.9.x` | 仅框架自身构建时编译 Less | 产物已把样式编译成 `dist/style.css`，**使用方无需安装 less** |
| `typescript` | `5.9.3` | 全仓编译与类型检查（唯一版本） | 不用 TS 7：`vue-tsc@3.3.14` 不支持（`ERR_PACKAGE_PATH_NOT_EXPORTED`）；`vue-tsgo@0.3.0` 实测在 pnpm monorepo 下模块解析失败（22 错）。等 vue-tsc 4.x 稳定后整体跟进 |
| `vue-tsc` | `3.3.x` | 对 `.vue` 做类型检查 | 运行时包与示例项目的 typecheck 用它 |
| `@types/node` | `26.x` | 插件侧的 Node 类型 | 仅 `@rinova/playground-vite` |

### 绝对禁止

- UI 组件库、CSS 框架（Tailwind/UnoCSS）作为**框架自身样式**来源（用户的样式体系不干预，但框架样式必须自洽）
- 任何 telemetry / 埋点 / 远程字体 / 远程 CDN 依赖（离线可用是硬要求）
- 第二套代码高亮引擎（Prism / highlight.js）与 Monaco 自带 monarch 高亮并存

## 3. 自研基础组件（只在 playground 内部使用）

全部 headless 逻辑 + CSS 变量样式，**不对外承诺 API 稳定性**，也不进入公共导出，避免变成第二套 UI 库。

| 组件 | 职责 | 不做 |
|---|---|---|
| `PwButton` | 主/次/文字/图标四种形态，loading、disabled | 不做按钮组、不做 popconfirm |
| `PwInput` | 单行输入、清除、搜索变体、前缀/后缀插槽 | 不做校验规则引擎 |
| `PwSelect` | 简单单选下拉（键盘可达） | 不做多选、远程搜索、分组 |
| `PwSwitch` | 布尔开关 | — |
| `PwTooltip` | hover / focus 提示 | 不做富文本气泡 |
| `PwPopover` | 锚点浮层，供菜单 / 更多操作 | 不做拖拽、不做多级 |
| `PwDialog` | 模态框：焦点陷阱、Esc 关闭、滚动锁 | 不做抽屉、不做嵌套栈 |
| `PwToast` | 轻提示（替代 `ElMessage`） | 不做通知中心 |

内部基础设施（不渲染 UI）：`PwPortal`（Teleport 封装）、`PwFocusTrap`、`PwIcon`（lucide 包装，统一尺寸与描边）。

**规模控制**：以上合计目标 ≤ 900 行（含样式），超出即说明范围失控。

## 4. 主题变量（外壳唯一颜色来源）

```css
:root {
  --rp-color-bg: #ffffff;
  --rp-color-surface: #f7f8fa;
  --rp-color-border: #e5e7eb;
  --rp-color-text: #1f2328;
  --rp-color-text-muted: #6b7280;
  --rp-color-primary: #2f6feb;
  --rp-color-primary-contrast: #ffffff;
  --rp-color-success: #1a7f37;
  --rp-color-warning: #b7791f;
  --rp-color-danger: #d1242f;
  --rp-radius: 8px;
  --rp-font-mono: ui-monospace, SFMono-Regular, Menlo, monospace;
}
```

- 只有这 12 个变量；dark 主题是同一组变量的另一套取值
- 组件样式中**禁止出现十六进制色值**，全部走变量（构建期用 lint 规则卡住）
- 代码区配色不在这 12 个变量里，由 shiki 主题负责

## 4.5 包产物与使用方式

`@rinova/playground` 不再直接发源码，由 `vite build`（lib 模式）+ `vue-tsc` 产出：

| 产物 | 内容 |
|---|---|
| `dist/index.js` | ESM 入口，`vue` 与 `virtual:playground/*` 保持 external |
| `dist/style.css` | 12 个主题变量 + 全部组件样式 + Monaco 编辑器样式（已编译，无 Less 运行时）。lib 模式无法按 chunk 拆 CSS，所以 Monaco 的 ~120KB gz 样式会随首屏一起加载 |
| `dist/types/*.d.ts` | 类型声明，含 `shims.d.ts`（`virtual:playground/*` 的 ambient 声明） |
| `dist/assets/*.worker.js` | 仅 `editor.worker` 与 `ts.worker` 两个（`ts.worker` 约 11.6MB 未压缩，只在打开 TS/JS 文件时按需下载） |

使用方两行接入：

```ts
import '@rinova/playground/style.css'
import { createPlayground } from '@rinova/playground'
createPlayground()
```

好处：使用方不需要 `less`、不需要处理 TS 源码、Vite 预打包行为与普通依赖一致（避免出现两个 Vue 实例）。注意 `src/index.ts` 里 `import('...App.vue')` 的懒加载在 dist 里变成按需 chunk，首屏仍然不载入编辑器/高亮代码。

## 5. 代码编辑器规格

| 项 | 规格 |
|---|---|
| 版本 | `monaco-editor@0.57.0`（不使用 0.52 以与旧项目解耦） |
| 高亮 | `@shikijs/monaco` 注入 shiki highlighter；主题名 = shiki 主题名 |
| worker | 仅 `editor` + `ts` 两个（放弃 json/css/html 语义 worker） |
| 加载 | `import()` 懒加载，首次打开代码 Tab 触发；首屏零编辑器代码 |
| 体积预算 | 编辑器 chunk（含 ts worker）gzip ≤ 2.5MB |
| 默认模式 | 只读（保留搜索、折叠、选择复制、链接直达） |
| 编辑 | **不支持编辑**（v0.1 明确不做）：源码面板只读，提供复制、多文件 Tab、搜索与折叠 |
| 多文件 | 一个文件一个 Tab；同文件跨 Tab 复用同一 model |
| 布局 | `ResizeObserver` 驱动 `layout()`，不使用 `window.resize` |
| 降级 | worker 或编辑器加载失败 → 自动切换为静态 shiki 高亮块；> 2000 行同样降级 |
| 开关 | `codeViewer: 'monaco' \| 'shiki'`，默认 `monaco` |

**全局单例约束**：`self.MonacoEnvironment` 只允许在模块作用域赋值一次；多个入口重复声明会互相覆盖，表现为 worker 全部回落到默认实现。

## 6. 高亮一致性规则

1. 静态代码块与编辑器共用**同一个** highlighter 实例（application 级单例）
2. 主题只允许一个名字：`theme.code`
3. 静态块与编辑器的字体、字号、行高、内边距由同一份样式变量控制
4. 验收方式：同一段源码在两个位置截图取色，逐 token 比对

## 7. 代码规范（`scripts/verify-m0.mjs` 强制）

| 规则 | 说明 |
|---|---|
| 只写 TypeScript | 框架包与示例的源码一律 `.ts` / `.vue`（`<script setup lang="ts">`），不留 `.js/.mjs/.cjs`；`@rinova/playground-vite` 用 `tsc` 构建到 `dist/`（含 `.d.ts`），dist 不进 git |
| 只允许箭头函数 | 禁止 `function` 声明与对象简写方法（`load(id) {}`），一律 `const fn = (...) => {}` / `load: async (id) => {}`。`.d.ts` 里用 `export declare const fn: (...) => T` |
| 样式只用 Less | 所有 `<style>` 必须带 `lang="less"`；共享变量与 mixin 放 `src/styles/mixins.less`，各组件用 `@import (reference) '../styles/mixins.less';` 引入（reference 不产出选择器） |
| 样式必须 scoped | 框架组件一律 `<style scoped lang="less">`，主题变量在 `styles/theme.less` |
| 颜色只走变量 | 组件样式禁止 `#hex` / `rgb()`；阴影用 `color-mix(in srgb, var(--rp-color-text) N%, transparent)` |

## 8. 版本与升级策略

- 每个依赖在 `packages/*/package.json` 写精确版本，升级需单独 PR 并附体积对比
- `monaco-editor` 升级必须复验：worker 产物数量、gzip 体积、`@shikijs/monaco` 兼容性
- `shiki` 与 `@shikijs/monaco` 必须同步升版（同一 monorepo 版本线）
